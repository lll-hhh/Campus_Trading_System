# 第8章 统计报表与可视化

## 8.1 同步统计报表

多数据库同步是本系统的核心特色功能，同步统计报表提供了对同步过程的全面监控和分析能力。通过统计报表，管理员可以实时了解同步状态、及时发现异常、分析性能瓶颈、优化同步策略。统计报表包括同步概览统计、性能趋势分析、冲突统计分析、错误日志分析等多个维度，为系统运维提供数据支撑。

**同步统计的重要性：**

第一，**实时监控**：通过实时统计数据，快速发现同步延迟、同步失败、冲突激增等异常情况，及时采取措施避免数据不一致扩大。第二，**性能优化**：分析同步耗时、吞吐量、瓶颈表等性能指标，识别性能瓶颈（如某个表同步特别慢），针对性优化（如增加索引、调整批次大小）。第三，**容量规划**：通过历史趋势数据，预测未来同步压力增长，提前扩容资源（如增加同步Worker数量、升级数据库硬件）。第四，**问题排查**：当用户报告数据不一致时，通过同步日志和统计数据，快速定位问题发生的时间、涉及的表、失败原因，加速故障恢复。第五，**审计合规**：完整的同步日志和统计报表满足审计要求，证明数据同步的可靠性和可追溯性。

### 8.1.1 同步概览统计

同步概览统计提供了系统级的同步健康度指标，是管理员打开监控页面后第一眼看到的核心数据。概览统计涵盖时间范围内的同步总次数、成功率、平均耗时、同步记录数等关键指标，以及按数据库、按表的细分统计，帮助管理员快速判断同步系统的整体状态。

**统计维度和指标设计：**

**总体指标（Overview Metrics）**：
- **total_syncs**：统计时间段内的同步总次数，反映同步系统的工作负荷。计算方式：COUNT(sync_logs)
- **success_count / failed_count**：成功和失败的同步次数，failed_count>0需要告警。计算方式：SUM(CASE WHEN status='success' THEN 1 ELSE 0 END)
- **success_rate**：同步成功率，核心健康指标。目标值>99.9%，低于95%需要紧急介入。计算方式：success_count / total_syncs * 100
- **avg_duration_ms**：平均同步耗时（毫秒），反映同步性能。目标值<100ms，超过500ms需要优化。计算方式：AVG(duration_ms)
- **total_records**：同步的记录总数，反映数据变更量。计算方式：SUM(records_synced)

**按数据库统计（By Database）**：
针对MySQL、PostgreSQL、MariaDB、SQLite四个数据库分别统计同步次数和平均耗时，识别哪个数据库同步压力最大、哪个数据库性能最差。某个数据库的同步次数远高于其他数据库，可能说明该数据库是主力生产库（最常被写入），需要重点关注；某个数据库的平均耗时明显高于其他数据库，可能说明该数据库性能瓶颈（网络延迟、磁盘IO慢、锁竞争），需要优化。

**按表统计（By Table Top 10）**：
统计同步次数最多的前10张表和同步记录数最多的前10张表。同步次数最多的表是热点表，反映用户操作的集中区域（如items表、transactions表），需要确保这些表的同步性能和可靠性；同步记录数最多的表是大表，单次同步可能耗时较长，需要考虑分批同步、增量同步等优化策略。

**代码实现（复杂SQL查询 + 数据聚合）：**

```python
# apps/monitoring_service/statistics.py - 同步统计服务模块
from datetime import datetime, timedelta
from typing import Dict, List, Optional
from sqlalchemy import select, func, case, desc, and_
from sqlalchemy.orm import Session
from core.database import db_manager
from apps.sync_service.models import SyncLog, ConflictRecord
import logging

logger = logging.getLogger(__name__)

class SyncStatistics:
    """
    同步统计服务
    
    提供多维度的同步统计和分析功能
    统计数据基于sync_logs表（同步日志）和conflict_records表（冲突记录）
    """
    
    def get_sync_overview(self, days: int = 7, target_db: Optional[str] = None) -> Dict:
        """
        获取同步概览统计
        
        统计指定时间段内的同步总体情况，包括：
        - 总体指标：同步次数、成功率、平均耗时、记录数
        - 按数据库统计：各数据库的同步次数和耗时
        - 按表统计：热点表的同步次数和记录数（Top 10）
        
        参数:
            days: 统计天数，默认7天（最近一周）
            target_db: 目标数据库筛选（可选），None表示所有数据库
        
        返回:
            Dict: 包含overview、by_database、by_table三部分的统计数据
        
        使用示例:
            stats = SyncStatistics()
            overview = stats.get_sync_overview(days=7)
            print(f"成功率: {overview['overview']['success_rate']}%")
        
        性能考虑:
            - 使用聚合查询（COUNT、SUM、AVG），数据库计算比Python快
            - 使用WHERE过滤时间范围，避免全表扫描
            - 使用GROUP BY分组统计，一次查询得到多行结果
            - 对于大数据量，可以添加LIMIT限制返回行数
        """
        
        with db_manager.session_scope("mysql") as session:
            # 计算时间范围
            end_date = datetime.utcnow()
            start_date = end_date - timedelta(days=days)
            
            logger.info(f"Generating sync overview statistics for {start_date} to {end_date}")
            
            # ============================================
            # 1. 总体统计（单行汇总数据）
            # ============================================
            # 构建基础查询条件
            base_filter = SyncLog.started_at >= start_date
            if target_db:
                base_filter = and_(base_filter, SyncLog.target_db == target_db)
            
            # SQLAlchemy复杂聚合查询
            total_stats = session.execute(
                select(
                    # 统计同步总次数
                    func.count(SyncLog.id).label("total_syncs"),
                    
                    # 统计成功次数（CASE表达式实现条件计数）
                    func.sum(
                        case((SyncLog.status == "success", 1), else_=0)
                    ).label("success_count"),
                    
                    # 统计失败次数
                    func.sum(
                        case((SyncLog.status == "failed", 1), else_=0)
                    ).label("failed_count"),
                    
                    # 统计部分成功次数（有冲突但主体成功）
                    func.sum(
                        case((SyncLog.status == "partial", 1), else_=0)
                    ).label("partial_count"),
                    
                    # 计算平均同步耗时（毫秒）
                    func.avg(SyncLog.duration_ms).label("avg_duration"),
                    
                    # 计算最大同步耗时（识别异常慢的同步）
                    func.max(SyncLog.duration_ms).label("max_duration"),
                    
                    # 计算最小同步耗时
                    func.min(SyncLog.duration_ms).label("min_duration"),
                    
                    # 统计同步记录总数
                    func.sum(SyncLog.records_synced).label("total_records")
                ).where(base_filter)
            ).fetchone()
            
            # 计算派生指标
            success_rate = 0
            if total_stats.total_syncs and total_stats.total_syncs > 0:
                success_rate = round(
                    (total_stats.success_count or 0) / total_stats.total_syncs * 100, 
                    2
                )
            
            # ============================================
            # 2. 按数据库统计（多行分组数据）
            # ============================================
            # 为每个目标数据库统计同步次数、成功率、耗时
            db_stats = session.execute(
                select(
                    SyncLog.target_db,
                    func.count(SyncLog.id).label("sync_count"),
                    func.sum(
                        case((SyncLog.status == "success", 1), else_=0)
                    ).label("success_count"),
                    func.avg(SyncLog.duration_ms).label("avg_duration"),
                    func.sum(SyncLog.records_synced).label("records_synced")
                )
                .where(SyncLog.started_at >= start_date)
                .group_by(SyncLog.target_db)  # 按数据库分组
                .order_by(desc("sync_count"))  # 按同步次数降序
            ).fetchall()
            
            # ============================================
            # 3. 按表统计（Top 10热点表）
            # ============================================
            # 统计同步次数最多的表（热点表）
            table_stats = session.execute(
                select(
                    SyncLog.table_name,
                    func.count(SyncLog.id).label("sync_count"),
                    func.sum(SyncLog.records_synced).label("records_synced"),
                    func.avg(SyncLog.duration_ms).label("avg_duration")
                )
                .where(base_filter)
                .group_by(SyncLog.table_name)
                .order_by(desc("sync_count"))  # 按同步次数降序
                .limit(10)  # 只取前10
            ).fetchall()
            
            # ============================================
            # 4. 同步操作类型统计（INSERT/UPDATE/DELETE）
            # ============================================
            operation_stats = session.execute(
                select(
                    SyncLog.operation_type,
                    func.count(SyncLog.id).label("count"),
                    func.sum(SyncLog.records_synced).label("records")
                )
                .where(base_filter)
                .group_by(SyncLog.operation_type)
            ).fetchall()
            
            # ============================================
            # 5. 同步延迟统计（时间差分析）
            # ============================================
            # 计算源数据库变更时间到目标数据库同步完成时间的延迟
            latency_stats = session.execute(
                select(
                    func.avg(
                        func.timestampdiff(
                            'SECOND', 
                            SyncLog.source_change_at,  # 源数据库变更时间
                            SyncLog.completed_at        # 同步完成时间
                        )
                    ).label("avg_latency_seconds"),
                    func.max(
                        func.timestampdiff(
                            'SECOND', 
                            SyncLog.source_change_at, 
                            SyncLog.completed_at
                        )
                    ).label("max_latency_seconds")
                )
                .where(
                    and_(
                        base_filter,
                        SyncLog.status == "success",
                        SyncLog.source_change_at.isnot(None)
                    )
                )
            ).fetchone()
            
            # ============================================
            # 6. 组装返回数据
            # ============================================
            return {
                "period": {
                    "days": days,
                    "start_date": start_date.strftime("%Y-%m-%d %H:%M:%S"),
                    "end_date": end_date.strftime("%Y-%m-%d %H:%M:%S"),
                    "target_db": target_db or "all"
                },
                "overview": {
                    "total_syncs": total_stats.total_syncs or 0,
                    "success_count": total_stats.success_count or 0,
                    "failed_count": total_stats.failed_count or 0,
                    "partial_count": total_stats.partial_count or 0,
                    "success_rate": success_rate,  # 百分比
                    "avg_duration_ms": round(total_stats.avg_duration or 0, 2),
                    "max_duration_ms": round(total_stats.max_duration or 0, 2),
                    "min_duration_ms": round(total_stats.min_duration or 0, 2),
                    "total_records": total_stats.total_records or 0,
                    # 添加健康度评级
                    "health_status": self._calculate_health_status(success_rate)
                },
                "by_database": [
                    {
                        "database": row.target_db,
                        "sync_count": row.sync_count,
                        "success_count": row.success_count,
                        "success_rate": round(row.success_count / row.sync_count * 100, 2) if row.sync_count else 100,
                        "avg_duration_ms": round(row.avg_duration, 2),
                        "records_synced": row.records_synced or 0
                    }
                    for row in db_stats
                ],
                "by_table": [
                    {
                        "table": row.table_name,
                        "sync_count": row.sync_count,
                        "records_synced": row.records_synced or 0,
                        "avg_duration_ms": round(row.avg_duration, 2),
                        # 计算每条记录平均耗时（性能指标）
                        "avg_ms_per_record": round(
                            row.avg_duration / row.records_synced, 4
                        ) if row.records_synced else 0
                    }
                    for row in table_stats
                ],
                "by_operation": [
                    {
                        "operation": row.operation_type,
                        "count": row.count,
                        "records": row.records
                    }
                    for row in operation_stats
                ],
                "latency": {
                    "avg_latency_seconds": round(latency_stats.avg_latency_seconds or 0, 2),
                    "max_latency_seconds": round(latency_stats.max_latency_seconds or 0, 2),
                    # 添加延迟评级
                    "latency_level": self._calculate_latency_level(latency_stats.avg_latency_seconds or 0)
                }
            }
    
    def _calculate_health_status(self, success_rate: float) -> str:
        """
        计算同步健康度等级
        
        分级标准:
        - excellent: 成功率 >= 99.5%
        - good: 成功率 >= 95%
        - warning: 成功率 >= 90%
        - critical: 成功率 < 90%
        """
        if success_rate >= 99.5:
            return "excellent"
        elif success_rate >= 95:
            return "good"
        elif success_rate >= 90:
            return "warning"
        else:
            return "critical"
    
    def _calculate_latency_level(self, avg_latency: float) -> str:
        """
        计算同步延迟等级
        
        分级标准:
        - excellent: 延迟 < 1秒
        - good: 延迟 < 5秒
        - warning: 延迟 < 30秒
        - critical: 延迟 >= 30秒
        """
        if avg_latency < 1:
            return "excellent"
        elif avg_latency < 5:
            return "good"
        elif avg_latency < 30:
            return "warning"
        else:
            return "critical"
```

### 8.1.2 同步性能趋势分析

同步性能趋势分析提供了时序维度的性能监控，帮助识别性能波动、发现异常峰值、预测未来趋势。与概览统计的单点数据不同，趋势分析展示的是性能指标随时间的变化曲线，更适合发现规律性问题（如每天某个时段同步变慢）和突发性问题（如某一时刻同步大量失败）。

**趋势分析的应用场景：**

**性能波动分析**：通过观察同步耗时的折线图，识别性能波动的规律。例如，如果每天下午2-4点同步耗时明显上升，可能是业务高峰期导致数据库负载高，需要错峰处理或增加资源。如果某一时刻出现孤立的性能尖刺（如从平时50ms突然跃升到5秒），需要查看该时刻的同步日志，分析是网络抖动、数据库死锁还是大批量数据同步导致。

**容量预测**：通过历史趋势数据拟合增长曲线，预测未来的同步压力。例如，如果同步次数以每月20%的速度增长，可以预测3个月后的同步量，提前规划资源扩容。如果同步耗时随数据量增长呈线性增长，可以预测何时会达到性能瓶颈（如单次同步超过1秒的阈值），需要引入分片、分批等优化手段。

**问题定位**：当用户报告某个时间段数据不同步时，通过趋势图快速定位该时间段的同步状态。如果趋势图显示该时间段同步成功率大幅下降或同步次数为0，说明同步系统确实出现问题；如果趋势图正常，可能是用户缓存问题或其他原因。

**代码实现（时间序列统计）：**

```python
# apps/monitoring_service/statistics.py - 性能趋势分析模块

def get_sync_performance_trends(
    self, 
    hours: int = 24, 
    granularity: str = "hour",
    target_db: Optional[str] = None
) -> Dict:
    """
    获取同步性能趋势（时间序列统计）
    
    按指定时间粒度（小时/日/周）统计同步性能指标随时间变化的趋势
    生成适合绘制折线图的时间序列数据
    
    参数:
        hours: 统计时间范围（小时数）
        granularity: 时间粒度 - 'hour'(小时)/'day'(天)/'week'(周)
        target_db: 目标数据库筛选（可选）
    
    返回:
        Dict: 包含时间序列数据点的字典，每个数据点包含时间戳和多个指标
    
    返回格式:
        {
            "period": {...},
            "data_points": [
                {
                    "time": "2025-12-21 14:00:00",
                    "total": 120,
                    "success": 118,
                    "failed": 2,
                    "success_rate": 98.33,
                    "avg_duration_ms": 45.2,
                    "max_duration_ms": 523,
                    "records_synced": 1520
                },
                ...
            ],
            "summary": {
                "peak_time": "2025-12-21 14:00:00",
                "peak_value": 150,
                "valley_time": "2025-12-21 03:00:00",
                "valley_value": 15
            }
        }
    
    使用场景:
        - 前端折线图渲染（时间为X轴，指标为Y轴）
        - 性能波动分析（识别波峰波谷）
        - 异常检测（识别超出正常范围的数据点）
    """
    
    with db_manager.session_scope("mysql") as session:
        end_time = datetime.utcnow()
        start_time = end_time - timedelta(hours=hours)
        
        logger.info(f"Generating sync performance trends: {granularity} from {start_time} to {end_time}")
        
        # 根据粒度选择时间格式化函数
        time_format_map = {
            "hour": '%Y-%m-%d %H:00:00',
            "day": '%Y-%m-%d',
            "week": '%Y-W%U'  # 年-周数
        }
        time_format = time_format_map.get(granularity, '%Y-%m-%d %H:00:00')
        
        # 构建查询条件
        base_filter = SyncLog.started_at >= start_time
        if target_db:
            base_filter = and_(base_filter, SyncLog.target_db == target_db)
        
        # 按时间分组统计（时间序列查询）
        hourly_stats = session.execute(
            select(
                # 时间分组字段（格式化为字符串）
                func.date_format(SyncLog.started_at, time_format).label("time_bucket"),
                
                # 同步总次数
                func.count(SyncLog.id).label("total"),
                
                # 成功次数
                func.sum(
                    case((SyncLog.status == "success", 1), else_=0)
                ).label("success"),
                
                # 失败次数
                func.sum(
                    case((SyncLog.status == "failed", 1), else_=0)
                ).label("failed"),
                
                # 平均耗时
                func.avg(SyncLog.duration_ms).label("avg_duration"),
                
                # 最大耗时（识别异常慢的同步）
                func.max(SyncLog.duration_ms).label("max_duration"),
                
                # 最小耗时
                func.min(SyncLog.duration_ms).label("min_duration"),
                
                # 同步记录数
                func.sum(SyncLog.records_synced).label("records_synced"),
                
                # 第95百分位耗时（P95）- 使用近似算法
                func.percentile_cont(0.95).within_group(
                    SyncLog.duration_ms.desc()
                ).label("p95_duration")
            )
            .where(base_filter)
            .group_by("time_bucket")  # 按时间分组
            .order_by("time_bucket")   # 按时间排序
        ).fetchall()
        
        # 转换为数据点列表
        data_points = []
        for row in hourly_stats:
            success_rate = round(row.success / row.total * 100, 2) if row.total else 100
            
            data_points.append({
                "time": row.time_bucket,
                "total": row.total,
                "success": row.success,
                "failed": row.failed,
                "success_rate": success_rate,
                "avg_duration_ms": round(row.avg_duration, 2),
                "max_duration_ms": round(row.max_duration, 2),
                "min_duration_ms": round(row.min_duration, 2),
                "p95_duration_ms": round(row.p95_duration, 2) if row.p95_duration else 0,
                "records_synced": row.records_synced or 0,
                # 添加健康度标记（用于前端高亮显示异常点）
                "health": self._calculate_health_status(success_rate),
                # 标记是否为异常点（成功率<95%或平均耗时>500ms）
                "is_anomaly": success_rate < 95 or row.avg_duration > 500
            })
        
        # 计算趋势摘要（峰值、谷值、平均值）
        summary = self._calculate_trend_summary(data_points)
        
        return {
            "period": {
                "hours": hours,
                "granularity": granularity,
                "start_time": start_time.strftime("%Y-%m-%d %H:%M:%S"),
                "end_time": end_time.strftime("%Y-%m-%d %H:%M:%S"),
                "target_db": target_db or "all"
            },
            "data_points": data_points,
            "summary": summary,
            # 添加前端渲染提示
            "chart_config": {
                "x_axis": "time",
                "y_axis_primary": "total",  # 主Y轴：同步次数
                "y_axis_secondary": "avg_duration_ms",  # 次Y轴：平均耗时
                "highlight_anomalies": True,  # 高亮异常点
                "show_trend_line": True  # 显示趋势线
            }
        }
    
    def _calculate_trend_summary(self, data_points: List[Dict]) -> Dict:
        """
        计算趋势摘要统计
        
        识别峰值、谷值、平均值等关键指标
        """
        if not data_points:
            return {}
        
        # 找出同步次数的峰值和谷值
        peak_point = max(data_points, key=lambda x: x["total"])
        valley_point = min(data_points, key=lambda x: x["total"])
        
        # 找出耗时最长的时间点
        slowest_point = max(data_points, key=lambda x: x["avg_duration_ms"])
        
        # 找出成功率最低的时间点
        lowest_success_point = min(data_points, key=lambda x: x["success_rate"])
        
        # 计算整体平均值
        avg_total = sum(p["total"] for p in data_points) / len(data_points)
        avg_duration = sum(p["avg_duration_ms"] for p in data_points) / len(data_points)
        avg_success_rate = sum(p["success_rate"] for p in data_points) / len(data_points)
        
        return {
            "peak": {
                "time": peak_point["time"],
                "value": peak_point["total"],
                "description": f"最高同步次数: {peak_point['total']}"
            },
            "valley": {
                "time": valley_point["time"],
                "value": valley_point["total"],
                "description": f"最低同步次数: {valley_point['total']}"
            },
            "slowest": {
                "time": slowest_point["time"],
                "value": slowest_point["avg_duration_ms"],
                "description": f"最慢平均耗时: {slowest_point['avg_duration_ms']}ms"
            },
            "lowest_success": {
                "time": lowest_success_point["time"],
                "value": lowest_success_point["success_rate"],
                "description": f"最低成功率: {lowest_success_point['success_rate']}%"
            },
            "averages": {
                "avg_total": round(avg_total, 2),
                "avg_duration_ms": round(avg_duration, 2),
                "avg_success_rate": round(avg_success_rate, 2)
            }
        }
```

### 8.1.3 冲突统计与分析

数据库同步过程中不可避免会遇到冲突（Conflict），即同一条记录在多个数据库中被并发修改，导致数据版本不一致。冲突统计提供了对冲突发生频率、冲突类型、冲突解决策略效果的全面分析，帮助优化同步策略和应用设计。

**冲突类型分类：**

**1. 更新冲突（Update-Update Conflict）**：最常见的冲突类型，两个数据库同时更新同一条记录的不同字段或相同字段。例如，用户在MySQL中将商品价格从100改为90，同时在PostgreSQL中将价格从100改为95，形成冲突。

**2. 删除冲突（Delete-Update Conflict）**：一个数据库删除记录，另一个数据库更新记录。例如，卖家在MySQL中删除了商品（下架），但买家在PostgreSQL中收藏了该商品，导致收藏表的item_id引用失效。

**3. 唯一约束冲突（Unique Constraint Conflict）**：两个数据库插入相同主键或唯一键的记录。例如，两个用户同时注册相同的用户名，在MySQL和PostgreSQL分别成功，同步时产生唯一约束冲突。

**冲突解决策略：**

**1. 最后写入获胜（Last Write Wins, LWW）**：基于时间戳选择最新的版本，简单高效但可能丢失数据。适用于低价值数据（如浏览记录）。

**2. 版本号冲突检测（Version-Based）**：每条记录维护version字段，更新时检查版本号，版本号不匹配说明有冲突。适用于需要严格一致性的数据（如账户余额）。

**3. 字段级合并（Field-Level Merge）**：对冲突记录的不同字段分别保留最新值，合并为一个版本。适用于字段独立的场景（如用户资料更新）。

**4. 人工介入（Manual Resolution）**：将冲突记录标记并通知管理员，人工判断保留哪个版本。适用于高价值数据（如交易金额）。

**代码实现（冲突统计和分析）：**

```python
# apps/monitoring_service/statistics.py - 冲突统计模块

def get_conflict_statistics(self, days: int = 7) -> Dict:
    """
    获取冲突统计
    
    统计同步冲突的发生频率、类型分布、解决策略效果
    为优化同步策略提供数据支撑
    
    参数:
        days: 统计天数
    
    返回:
        Dict: 冲突统计数据，包括总数、按类型统计、按表统计、按解决策略统计
    """
    
    with db_manager.session_scope("mysql") as session:
        end_date = datetime.utcnow()
        start_date = end_date - timedelta(days=days)
        
        # ============================================
        # 1. 冲突总体统计
        # ============================================
        total_conflicts = session.execute(
            select(
                func.count(ConflictRecord.id).label("total"),
                func.sum(
                    case((ConflictRecord.status == "resolved", 1), else_=0)
                ).label("resolved"),
                func.sum(
                    case((ConflictRecord.status == "pending", 1), else_=0)
                ).label("pending")
            ).where(ConflictRecord.detected_at >= start_date)
        ).fetchone()
        
        # ============================================
        # 2. 按冲突类型统计
        # ============================================
        conflict_types = session.execute(
            select(
                ConflictRecord.conflict_type,
                func.count(ConflictRecord.id).label("count"),
                func.avg(
                    func.timestampdiff(
                        'SECOND',
                        ConflictRecord.detected_at,
                        ConflictRecord.resolved_at
                    )
                ).label("avg_resolution_time")
            )
            .where(ConflictRecord.detected_at >= start_date)
            .group_by(ConflictRecord.conflict_type)
        ).fetchall()
        
        # ============================================
        # 3. 按表统计（哪些表冲突最多）
        # ============================================
        conflict_by_table = session.execute(
            select(
                ConflictRecord.table_name,
                func.count(ConflictRecord.id).label("count")
            )
            .where(ConflictRecord.detected_at >= start_date)
            .group_by(ConflictRecord.table_name)
            .order_by(desc("count"))
            .limit(10)
        ).fetchall()
        
        # ============================================
        # 4. 按解决策略统计（哪种策略最常用）
        # ============================================
        resolution_strategies = session.execute(
            select(
                ConflictRecord.resolution_strategy,
                func.count(ConflictRecord.id).label("count")
            )
            .where(
                and_(
                    ConflictRecord.detected_at >= start_date,
                    ConflictRecord.status == "resolved"
                )
            )
            .group_by(ConflictRecord.resolution_strategy)
        ).fetchall()
        
        # ============================================
        # 5. 冲突率趋势（每日冲突数）
        # ============================================
        daily_conflicts = session.execute(
            select(
                func.date(ConflictRecord.detected_at).label("date"),
                func.count(ConflictRecord.id).label("count")
            )
            .where(ConflictRecord.detected_at >= start_date)
            .group_by("date")
            .order_by("date")
        ).fetchall()
        
        # 计算冲突率（冲突数 / 同步数）
        total_syncs = session.execute(
            select(func.count(SyncLog.id))
            .where(SyncLog.started_at >= start_date)
        ).scalar() or 1
        
        conflict_rate = round((total_conflicts.total or 0) / total_syncs * 100, 4)
        
        return {
            "period": {
                "days": days,
                "start_date": start_date.strftime("%Y-%m-%d"),
                "end_date": end_date.strftime("%Y-%m-%d")
            },
            "overview": {
                "total_conflicts": total_conflicts.total or 0,
                "resolved": total_conflicts.resolved or 0,
                "pending": total_conflicts.pending or 0,
                "resolution_rate": round(
                    (total_conflicts.resolved or 0) / (total_conflicts.total or 1) * 100, 2
                ),
                "conflict_rate": conflict_rate,  # 冲突率（%）
                "status": "warning" if conflict_rate > 1 else "normal"
            },
            "by_type": [
                {
                    "type": row.conflict_type,
                    "count": row.count,
                    "avg_resolution_time_seconds": round(row.avg_resolution_time or 0, 2)
                }
                for row in conflict_types
            ],
            "by_table": [
                {"table": row.table_name, "count": row.count}
                for row in conflict_by_table
            ],
            "by_strategy": [
                {"strategy": row.resolution_strategy, "count": row.count}
                for row in resolution_strategies
            ],
            "daily_trend": [
                {"date": str(row.date), "count": row.count}
                for row in daily_conflicts
            ]
        }
```

## 8.2 业务数据统计

业务数据统计聚焦于应用层面的关键业务指标（KPI），包括交易金额、用户活跃度、商品销售排行、收入增长等，帮助运营人员和管理层了解平台的商业表现。与同步统计（8.1节）关注技术指标不同，业务统计面向业务决策，需要将底层数据转化为可操作的商业洞察。

### 8.2.1 交易统计分析

交易统计是电商平台的核心业务指标，直接反映平台的盈利能力和运营健康度。通过分析交易数量、交易金额、完成率、客单价等指标，可以识别收入增长趋势、优化营销策略、预测未来业绩。

**关键指标设计：**

**1. 交易总览指标**：总交易数、完成交易数、交易完成率、总交易金额、平均客单价（AOV, Average Order Value）。这些指标提供整体业绩快照，是管理层最关心的数据。例如，总交易金额直接反映平台收入，完成率反映用户体验和支付成功率，客单价反映用户消费能力。

**2. 时序趋势指标**：每日/每周/每月交易数和交易金额的变化曲线。通过趋势图可以识别增长模式（如持续增长、平稳、下降）、季节性规律（如节假日高峰）、突发事件影响（如促销活动）。例如，如果发现每周六交易量是平时的2倍，可以在周六增加客服人员和服务器资源。

**3. 分类交易统计**：按商品分类统计交易数和金额，识别热门品类和潜力品类。例如，如果"电子产品"分类占总交易金额的40%，说明这是核心品类，需要重点运营；如果"图书"分类交易数多但金额低，说明是流量入口但利润薄，可以作为引流品类。

**4. 支付方式统计**：统计不同支付方式（支付宝、微信、银行卡）的使用频率和成功率，优化支付流程。例如，如果发现银行卡支付成功率只有80%而其他方式95%+，需要排查银行卡支付接口问题。

**代码实现（交易统计全维度分析）：**

```python
# apps/monitoring_service/business_statistics.py - 业务统计模块

class BusinessStatistics:
    """
    业务统计服务
    
    提供面向业务决策的统计分析功能，包括交易、用户、商品等维度
    与技术监控（SyncStatistics）分离，专注业务指标
    """
    
    def __init__(self, db_manager):
        self.db_manager = db_manager
        self.logger = logging.getLogger(__name__)
    
    def get_transaction_statistics(
        self, 
        days: int = 30, 
        breakdown: str = "daily"
    ) -> Dict:
        """
        获取交易统计（全维度分析）
        
        统计指定时间范围内的交易数据，包括金额、数量、完成率、趋势等
        支持多维度下钻分析（分类、用户、时间）
        
        参数:
            days: 统计天数（默认30天，支持7/30/90/365）
            breakdown: 时间粒度 - 'daily'(按天)/'weekly'(按周)/'monthly'(按月)
        
        返回:
            Dict: 包含6个部分的交易统计数据
                - overview: 交易总览
                - trends: 时序趋势
                - by_category: 按分类统计
                - by_payment_method: 按支付方式统计
                - by_user_segment: 按用户分层统计
                - insights: 自动生成的业务洞察
        """
        
        with self.db_manager.session_scope("mysql") as session:
            end_date = datetime.utcnow()
            start_date = end_date - timedelta(days=days)
            
            self.logger.info(f"Generating transaction statistics: {days} days, breakdown={breakdown}")
            
            # ============================================
            # 1. 交易总览统计
            # ============================================
            overview = session.execute(
                select(
                    # 总交易数
                    func.count(Transaction.id).label("total_transactions"),
                    
                    # 已完成交易数
                    func.sum(
                        case((Transaction.status == "completed", 1), else_=0)
                    ).label("completed"),
                    
                    # 待支付交易数
                    func.sum(
                        case((Transaction.status == "pending", 1), else_=0)
                    ).label("pending"),
                    
                    # 已取消交易数
                    func.sum(
                        case((Transaction.status == "cancelled", 1), else_=0)
                    ).label("cancelled"),
                    
                    # 总交易金额（仅统计已完成）
                    func.sum(
                        case(
                            (Transaction.status == "completed", Transaction.total_price),
                            else_=0
                        )
                    ).label("total_amount"),
                    
                    # 平均客单价（Average Order Value）
                    func.avg(
                        case(
                            (Transaction.status == "completed", Transaction.total_price),
                            else_=None
                        )
                    ).label("avg_amount"),
                    
                    # 最高单笔交易
                    func.max(
                        case(
                            (Transaction.status == "completed", Transaction.total_price),
                            else_=0
                        )
                    ).label("max_amount"),
                    
                    # 独立买家数（去重）
                    func.count(func.distinct(Transaction.buyer_id)).label("unique_buyers"),
                    
                    # 独立卖家数（去重）
                    func.count(func.distinct(Transaction.seller_id)).label("unique_sellers")
                ).where(Transaction.created_at >= start_date)
            ).fetchone()
            
            # 计算衍生指标
            completion_rate = (
                overview.completed / overview.total_transactions * 100
                if overview.total_transactions else 0
            )
            
            cancellation_rate = (
                overview.cancelled / overview.total_transactions * 100
                if overview.total_transactions else 0
            )
            
            # 每用户平均交易数（ARPU - Average Revenue Per User）
            transactions_per_user = (
                overview.completed / overview.unique_buyers
                if overview.unique_buyers else 0
            )
            
            # ============================================
            # 2. 时序趋势统计
            # ============================================
            # 根据breakdown选择时间格式
            time_format_map = {
                "daily": '%Y-%m-%d',
                "weekly": '%Y-W%U',
                "monthly": '%Y-%m'
            }
            time_format = time_format_map.get(breakdown, '%Y-%m-%d')
            
            daily_trends = session.execute(
                select(
                    func.date_format(Transaction.created_at, time_format).label("period"),
                    func.count(Transaction.id).label("count"),
                    func.sum(
                        case((Transaction.status == "completed", 1), else_=0)
                    ).label("completed"),
                    func.sum(
                        case(
                            (Transaction.status == "completed", Transaction.total_price),
                            else_=0
                        )
                    ).label("amount"),
                    func.count(func.distinct(Transaction.buyer_id)).label("buyers")
                )
                .where(Transaction.created_at >= start_date)
                .group_by("period")
                .order_by("period")
            ).fetchall()
            
            # ============================================
            # 3. 按分类统计（Top 10热门分类）
            # ============================================
            category_stats = session.execute(
                select(
                    Category.id,
                    Category.name,
                    func.count(Transaction.id).label("transaction_count"),
                    func.sum(
                        case(
                            (Transaction.status == "completed", Transaction.total_price),
                            else_=0
                        )
                    ).label("total_amount"),
                    func.avg(
                        case(
                            (Transaction.status == "completed", Transaction.total_price),
                            else_=None
                        )
                    ).label("avg_price")
                )
                .join(Item, Transaction.item_id == Item.id)
                .join(Category, Item.category_id == Category.id)
                .where(
                    Transaction.created_at >= start_date,
                    Transaction.status == "completed"
                )
                .group_by(Category.id, Category.name)
                .order_by(desc("total_amount"))
                .limit(10)
            ).fetchall()
            
            # ============================================
            # 4. 按支付方式统计
            # ============================================
            payment_stats = session.execute(
                select(
                    Transaction.payment_method,
                    func.count(Transaction.id).label("count"),
                    func.sum(
                        case((Transaction.status == "completed", 1), else_=0)
                    ).label("success_count"),
                    func.sum(Transaction.total_price).label("total_amount")
                )
                .where(Transaction.created_at >= start_date)
                .group_by(Transaction.payment_method)
            ).fetchall()
            
            # ============================================
            # 5. 用户分层统计（新用户 vs 老用户）
            # ============================================
            user_segment_query = text("""
                SELECT 
                    CASE 
                        WHEN u.created_at >= :start_date THEN 'new'
                        ELSE 'returning'
                    END AS user_segment,
                    COUNT(t.id) AS transaction_count,
                    SUM(CASE WHEN t.status = 'completed' THEN t.total_price ELSE 0 END) AS total_amount,
                    COUNT(DISTINCT t.buyer_id) AS buyer_count
                FROM transactions t
                JOIN users u ON t.buyer_id = u.id
                WHERE t.created_at >= :start_date
                GROUP BY user_segment
            """)
            
            user_segments = session.execute(
                user_segment_query,
                {"start_date": start_date}
            ).fetchall()
            
            # ============================================
            # 6. 自动生成业务洞察
            # ============================================
            insights = self._generate_transaction_insights(
                overview, daily_trends, category_stats
            )
            
            return {
                "period": {
                    "days": days,
                    "start_date": start_date.strftime("%Y-%m-%d"),
                    "end_date": end_date.strftime("%Y-%m-%d"),
                    "breakdown": breakdown
                },
                "overview": {
                    "total_transactions": overview.total_transactions or 0,
                    "completed_transactions": overview.completed or 0,
                    "pending_transactions": overview.pending or 0,
                    "cancelled_transactions": overview.cancelled or 0,
                    "completion_rate": round(completion_rate, 2),
                    "cancellation_rate": round(cancellation_rate, 2),
                    "total_amount": float(overview.total_amount or 0),
                    "avg_amount": round(float(overview.avg_amount or 0), 2),
                    "max_amount": float(overview.max_amount or 0),
                    "unique_buyers": overview.unique_buyers or 0,
                    "unique_sellers": overview.unique_sellers or 0,
                    "transactions_per_user": round(transactions_per_user, 2)
                },
                "trends": [
                    {
                        "period": row.period,
                        "count": row.count,
                        "completed": row.completed,
                        "amount": float(row.amount),
                        "buyers": row.buyers,
                        "completion_rate": round(row.completed / row.count * 100, 2) if row.count else 100
                    }
                    for row in daily_trends
                ],
                "by_category": [
                    {
                        "category_id": row.id,
                        "category_name": row.name,
                        "transaction_count": row.transaction_count,
                        "total_amount": float(row.total_amount),
                        "avg_price": round(float(row.avg_price), 2)
                    }
                    for row in category_stats
                ],
                "by_payment_method": [
                    {
                        "method": row.payment_method,
                        "count": row.count,
                        "success_count": row.success_count,
                        "success_rate": round(row.success_count / row.count * 100, 2) if row.count else 100,
                        "total_amount": float(row.total_amount or 0)
                    }
                    for row in payment_stats
                ],
                "by_user_segment": [
                    {
                        "segment": row.user_segment,
                        "transaction_count": row.transaction_count,
                        "total_amount": float(row.total_amount),
                        "buyer_count": row.buyer_count
                    }
                    for row in user_segments
                ],
                "insights": insights
            }
    
    def _generate_transaction_insights(
        self, 
        overview, 
        trends, 
        categories
    ) -> List[Dict]:
        """
        自动生成业务洞察
        
        基于统计数据自动识别关键发现和建议
        """
        insights = []
        
        # 洞察1：完成率健康度
        completion_rate = (
            overview.completed / overview.total_transactions * 100
            if overview.total_transactions else 100
        )
        
        if completion_rate < 70:
            insights.append({
                "type": "warning",
                "title": "交易完成率偏低",
                "description": f"当前完成率为{completion_rate:.1f}%，低于行业基准70%",
                "suggestion": "检查支付流程是否存在障碍，优化用户体验"
            })
        elif completion_rate > 90:
            insights.append({
                "type": "positive",
                "title": "交易完成率优秀",
                "description": f"当前完成率为{completion_rate:.1f}%，高于行业平均",
                "suggestion": "保持当前支付流程，可作为最佳实践推广"
            })
        
        # 洞察2：趋势分析
        if len(trends) >= 7:
            recent_week = sum(t.amount for t in trends[-7:])
            previous_week = sum(t.amount for t in trends[-14:-7]) if len(trends) >= 14 else recent_week
            
            growth_rate = (
                (recent_week - previous_week) / previous_week * 100
                if previous_week > 0 else 0
            )
            
            if growth_rate > 10:
                insights.append({
                    "type": "positive",
                    "title": "交易额快速增长",
                    "description": f"近7天交易额较前7天增长{growth_rate:.1f}%",
                    "suggestion": "把握增长势头，增加营销投入"
                })
            elif growth_rate < -10:
                insights.append({
                    "type": "warning",
                    "title": "交易额下降",
                    "description": f"近7天交易额较前7天下降{abs(growth_rate):.1f}%",
                    "suggestion": "分析下降原因，可能需要促销活动"
                })

        if categories:

### 8.2.2 用户活跃度分析

用户活跃度反映平台的用户参与度和留存情况，是衡量产品健康度的关键指标。通过分析DAU（日活跃用户）、MAU（月活跃用户）、留存率、用户行为路径等，可以优化产品功能、提升用户粘性。

**核心指标定义：**

**1. DAU/MAU/WAU（活跃用户指标）**：DAU（Daily Active Users）统计每日至少执行一次操作（发布商品、交易、消息）的独立用户数；MAU（Monthly Active Users）统计30天内活跃用户数；WAU（Weekly Active Users）统计7天内活跃用户数。通过DAU/MAU比值可以计算用户粘性（Stickiness），比值越高说明用户越频繁使用。

**2. 留存率（Retention Rate）**：新用户在注册后第1/7/30天仍然活跃的比例。例如，次日留存率40%表示100个新用户中有40个在注册第二天还会回来使用。留存率是评估产品吸引力的核心指标，低留存率说明产品未能满足用户需求。

**3. 用户分层（User Segmentation）**：按活跃度将用户分为核心用户（每天使用）、活跃用户（每周使用）、普通用户（每月使用）、流失用户（30天未使用）。不同层级用户的运营策略不同：核心用户需要VIP特权留住，流失用户需要召回活动激活。

**代码实现（用户活跃度全维度统计）：**

```python
def get_user_activity_statistics(self, days: int = 30) -> Dict:
    """
    获取用户活跃度统计
    
    统计DAU/MAU/WAU、留存率、用户分层等指标
    帮助了解用户参与度和产品粘性
    
    参数:
        days: 统计天数
    
    返回:
        Dict: 包含活跃度、留存、分层等多维度数据
    """
    
    with self.db_manager.session_scope("mysql") as session:
        end_date = datetime.utcnow()
        start_date = end_date - timedelta(days=days)
        
        # ============================================
        # 1. DAU（日活跃用户）统计
        # ============================================
        # 定义活跃：发布商品、交易、发送消息、收藏、评论等操作
        dau_query = text("""
            SELECT 
                DATE(activity_date) AS date,
                COUNT(DISTINCT user_id) AS active_users
            FROM (
                SELECT buyer_id AS user_id, created_at AS activity_date FROM transactions
                UNION ALL
                SELECT seller_id AS user_id, created_at AS activity_date FROM items
                UNION ALL
                SELECT sender_id AS user_id, created_at AS activity_date FROM messages
                UNION ALL
                SELECT user_id, created_at AS activity_date FROM favorites
                UNION ALL
                SELECT user_id, created_at AS activity_date FROM comments
            ) AS user_activities
            WHERE activity_date >= :start_date
            GROUP BY DATE(activity_date)
            ORDER BY date
        """)
        
        dau_data = session.execute(
            dau_query,
            {"start_date": start_date}
        ).fetchall()
        
        # ============================================
        # 2. MAU/WAU计算
        # ============================================
        # MAU：过去30天内至少活跃一次的用户数
        mau = session.execute(
            text("""
                SELECT COUNT(DISTINCT user_id) AS mau
                FROM (
                    SELECT buyer_id AS user_id FROM transactions WHERE created_at >= DATE_SUB(NOW(), INTERVAL 30 DAY)
                    UNION
                    SELECT seller_id FROM items WHERE created_at >= DATE_SUB(NOW(), INTERVAL 30 DAY)
                    UNION
                    SELECT sender_id FROM messages WHERE created_at >= DATE_SUB(NOW(), INTERVAL 30 DAY)
                ) AS active_users
            """)
        ).scalar()
        
        # WAU：过去7天内至少活跃一次的用户数
        wau = session.execute(
            text("""
                SELECT COUNT(DISTINCT user_id)
                FROM (
                    SELECT buyer_id AS user_id FROM transactions WHERE created_at >= DATE_SUB(NOW(), INTERVAL 7 DAY)
                    UNION
                    SELECT seller_id FROM items WHERE created_at >= DATE_SUB(NOW(), INTERVAL 7 DAY)
                    UNION
                    SELECT sender_id FROM messages WHERE created_at >= DATE_SUB(NOW(), INTERVAL 7 DAY)
                ) AS active_users
            """)
        ).scalar()
        
        # 计算粘性（Stickiness = DAU/MAU）
        latest_dau = dau_data[-1].active_users if dau_data else 0
        stickiness = (latest_dau / mau * 100) if mau > 0 else 0
        
        # ============================================
        # 3. 用户留存率（Cohort Analysis）
        # ============================================
        retention_query = text("""
            WITH user_cohorts AS (
                SELECT 
                    id AS user_id,
                    DATE(created_at) AS cohort_date
                FROM users
                WHERE created_at >= :start_date
            ),
            user_activities AS (
                SELECT DISTINCT
                    user_id,
                    DATE(activity_date) AS activity_date
                FROM (
                    SELECT buyer_id AS user_id, created_at AS activity_date FROM transactions
                    UNION ALL
                    SELECT seller_id, created_at FROM items
                    UNION ALL
                    SELECT sender_id, created_at FROM messages
                ) AS activities
            )
            SELECT 
                uc.cohort_date,
                COUNT(DISTINCT uc.user_id) AS cohort_size,
                COUNT(DISTINCT CASE WHEN DATEDIFF(ua.activity_date, uc.cohort_date) = 1 THEN uc.user_id END) AS day1_retained,
                COUNT(DISTINCT CASE WHEN DATEDIFF(ua.activity_date, uc.cohort_date) = 7 THEN uc.user_id END) AS day7_retained,
                COUNT(DISTINCT CASE WHEN DATEDIFF(ua.activity_date, uc.cohort_date) = 30 THEN uc.user_id END) AS day30_retained
            FROM user_cohorts uc
            LEFT JOIN user_activities ua ON uc.user_id = ua.user_id
            GROUP BY uc.cohort_date
            HAVING cohort_size > 0
            ORDER BY uc.cohort_date
        """)
        
        retention_data = session.execute(
            retention_query,
            {"start_date": start_date}
        ).fetchall()
        
        # ============================================
        # 4. 用户分层统计
        # ============================================
        user_segmentation_query = text("""
            WITH user_activity_counts AS (
                SELECT 
                    user_id,
                    COUNT(*) AS activity_count,
                    MAX(activity_date) AS last_activity
                FROM (
                    SELECT buyer_id AS user_id, created_at AS activity_date FROM transactions WHERE created_at >= :start_date
                    UNION ALL
                    SELECT seller_id, created_at FROM items WHERE created_at >= :start_date
                    UNION ALL
                    SELECT sender_id, created_at FROM messages WHERE created_at >= :start_date
                ) AS activities
                GROUP BY user_id
            )
            SELECT 
                CASE 
                    WHEN activity_count >= 30 THEN 'core'
                    WHEN activity_count >= 10 THEN 'active'
                    WHEN activity_count >= 3 THEN 'regular'
                    ELSE 'occasional'
                END AS user_segment,
                COUNT(*) AS user_count,
                AVG(activity_count) AS avg_activities
            FROM user_activity_counts
            GROUP BY user_segment
        """)
        
        segmentation_data = session.execute(
            user_segmentation_query,
            {"start_date": start_date}
        ).fetchall()
        
        return {
            "period": {
                "days": days,
                "start_date": start_date.strftime("%Y-%m-%d"),
                "end_date": end_date.strftime("%Y-%m-%d")
            },
            "overview": {
                "dau": latest_dau,
                "wau": wau or 0,
                "mau": mau or 0,
                "stickiness": round(stickiness, 2),
                "dau_wau_ratio": round((latest_dau / wau * 100) if wau > 0 else 0, 2),
                "wau_mau_ratio": round((wau / mau * 100) if mau > 0 else 0, 2)
            },
            "dau_trend": [
                {
                    "date": str(row.date),
                    "active_users": row.active_users
                }
                for row in dau_data
            ],
            "retention": [
                {
                    "cohort_date": str(row.cohort_date),
                    "cohort_size": row.cohort_size,
                    "day1_retention_rate": round(row.day1_retained / row.cohort_size * 100, 2),
                    "day7_retention_rate": round(row.day7_retained / row.cohort_size * 100, 2),
                    "day30_retention_rate": round(row.day30_retained / row.cohort_size * 100, 2)
                }
                for row in retention_data
            ],
            "segmentation": [
                {
                    "segment": row.user_segment,
                    "user_count": row.user_count,
                    "avg_activities": round(row.avg_activities, 2)
                }
                for row in segmentation_data
            ]
        }
```

## 8.3 数据可视化

数据可视化将复杂的统计数据转化为直观的图表、仪表盘、实时监控面板,帮助用户快速理解数据趋势和异常。本节介绍前端图表组件、实时监控面板、数据导出功能的实现。

### 8.3.1 前端图表组件

前端图表组件基于ECharts（Apache ECharts）图表库实现，封装为Vue组件以便复用。通过API获取后端统计数据，渲染为折线图、柱状图、饼图、散点图等多种图表类型，支持交互式操作（缩放、数据点提示、图例切换）。

**ECharts选型理由：**

ECharts是百度开源的JavaScript可视化库，功能强大且社区活跃。相比Chart.js、D3.js等替代方案，ECharts的优势包括：(1) 开箱即用，配置简单；(2) 图表类型丰富（50+种）；(3) 性能优秀，支持大数据量渲染（10万+数据点）；(4) 移动端适配好，支持触摸操作；(5) 中文文档完善，学习成本低。

**图表组件设计原则：**

**1. 数据与视图分离**：组件通过props接收数据源URL或静态数据，内部负责数据请求和图表渲染。父组件无需关心ECharts API细节，只需传递配置参数（如时间范围、筛选条件）。

**2. 响应式更新**：使用Vue的watch监听props变化，数据更新时自动重新请求并刷新图表。支持时间范围切换（如从7天切换到30天）、数据库筛选（如只显示MySQL同步数据）等交互操作。

**3. 自适应布局**：图表容器使用百分比宽度（width: 100%），高度固定（如400px）或根据父容器自适应。窗口resize时调用chart.resize()重新计算尺寸，确保图表不变形。

### 8.3.2 实时监控面板

实时监控面板通过WebSocket推送实时指标更新，展示系统的当前状态（如在线用户数、正在进行的同步任务、最新交易）。与定时轮询（Polling）相比，WebSocket的优势是服务端主动推送，延迟低（<100ms）、流量小（无重复HTTP头），适合实时性要求高的场景。

**WebSocket通信流程：**

1. **连接建立**：前端通过`new WebSocket('ws://localhost:8000/ws/monitoring')`建立连接，后端FastAPI使用`@app.websocket('/ws/monitoring')`接收。

2. **订阅主题**：前端发送订阅消息`{type: 'subscribe', topic: 'metrics'}`，后端将该连接加入对应主题的订阅列表。

3. **数据推送**：后端监控任务每5秒计算一次最新指标（同步状态、交易数、在线用户数），通过`await websocket.send_json(data)`推送给所有订阅者。

4. **断线重连**：前端检测到连接关闭（onclose事件），自动重连（最多重试5次，指数退避间隔）。

**代码实现（实时监控面板）：**

```vue

const alerts = ref<Array<{
  id: string
  type: 'error' | 'warning' | 'info'
  message: string
  timestamp: string
}>>([])

// 连接状态指示器
const connectionStatus = computed(() => {
  return isConnected.value ? 'connected' : 'disconnected'
})

onMounted(() => {
  // 建立WebSocket连接
  connect()
  
  // 监听指标更新事件
  on('metrics_update', (data: any) => {
    metrics.value = data
    
    // 检查是否需要告警
    checkAlerts(data)
  })
  
  // 监听告警事件
  on('alert', (alert: any) => {
    alerts.value.unshift(alert)
    
    // 最多保留50条告警
    if (alerts.value.length > 50) {
      alerts.value.pop()
    }
    
    // 桌面通知（需要用户授权）
    if (Notification.permission === 'granted' && alert.type === 'error') {
      new Notification('系统告警', {
        body: alert.message,
        icon: '/favicon.ico'
      })
    }
  })
  
  // 请求初始数据
  send('subscribe', { topic: 'metrics' })
  
  // 请求通知权限
  if (Notification.permission === 'default') {
    Notification.requestPermission()
  }
})

onUnmounted(() => {
  // 断开WebSocket连接
  disconnect()
})

const checkAlerts = (data: any) => {
  // 检查同步成功率
  if (data.sync.success_rate < 90) {
    addAlert('warning', `同步成功率偏低: ${data.sync.success_rate}%`)
  }
  
  // 检查同步耗时
  if (data.sync.avg_duration_ms > 1000) {
    addAlert('warning', `同步耗时过高: ${data.sync.avg_duration_ms}ms`)
  }
  
  // 检查系统资源
  if (data.system.cpu_usage > 80) {
    addAlert('error', `CPU使用率过高: ${data.system.cpu_usage}%`)
  }
  
  if (data.system.memory_usage > 90) {
    addAlert('error', `内存使用率过高: ${data.system.memory_usage}%`)
  }
}

const addAlert = (type: 'error' | 'warning' | 'info', message: string) => {
  const alert = {
    id: Date.now().toString(),
    type,
    message,
    timestamp: new Date().toLocaleString()
  }
  
  // 避免重复告警（5分钟内相同消息只告警一次）
  const recentAlert = alerts.value.find(
    a => a.message === message && 
    (Date.now() - new Date(a.timestamp).getTime()) < 5 * 60 * 1000
  )
  
  if (!recentAlert) {
    alerts.value.unshift(alert)
  }
}

const handleDismissAlert = (id: string) => {
  const index = alerts.value.findIndex(a => a.id === id)
  if (index !== -1) {
    alerts.value.splice(index, 1)
  }
}

### 8.3.3 数据导出功能

数据导出功能允许用户将统计报表导出为Excel、CSV、PDF等格式，便于离线分析、归档存储或向上级汇报。后端使用openpyxl（Excel）、reportlab（PDF）库生成文件，前端通过Blob下载。

**代码实现（后端导出API）：**

```python
# apps/monitoring_service/export.py - 数据导出模块

from fastapi import APIRouter, Query
from fastapi.responses import StreamingResponse
from io import BytesIO
import openpyxl
from openpyxl.styles import Font, Alignment, PatternFill
from reportlab.lib.pagesizes import A4
from reportlab.pdfgen import canvas
from datetime import datetime

router = APIRouter(prefix="/monitoring/export", tags=["export"])

@router.get("/sync-statistics/excel")
async def export_sync_statistics_excel(
    days: int = Query(30, ge=1, le=365)
):
    """
    导出同步统计为Excel文件
    
    生成多Sheet Excel：
    - Sheet1: 概览统计
    - Sheet2: 时序趋势
    - Sheet3: 按数据库统计
    - Sheet4: 按表统计
    """
    
    # 获取统计数据
    sync_stats = SyncStatistics(db_manager)
    overview = sync_stats.get_sync_overview(days=days)
    trends = sync_stats.get_sync_performance_trends(hours=days*24, granularity="day")
    
    # 创建Excel工作簿
    wb = openpyxl.Workbook()
    
    # ========== Sheet1: 概览统计 ==========
    ws1 = wb.active
    ws1.title = "概览统计"
    
    # 表头样式
    header_fill = PatternFill(start_color="4472C4", end_color="4472C4", fill_type="solid")
    header_font = Font(bold=True, color="FFFFFF")
    
    # 写入标题
    ws1['A1'] = "同步概览统计"
    ws1['A1'].font = Font(size=16, bold=True)
    
    # 写入统计指标
    ws1['A3'] = "指标"
    ws1['B3'] = "值"
    ws1['A3'].fill = header_fill
    ws1['B3'].fill = header_fill
    ws1['A3'].font = header_font
    ws1['B3'].font = header_font
    
    row = 4
    for key, value in overview['total'].items():
        ws1[f'A{row}'] = key
        ws1[f'B{row}'] = value
        row += 1
    
    # ========== Sheet2: 时序趋势 ==========
    ws2 = wb.create_sheet("时序趋势")
    ws2.append(["时间", "总同步数", "成功数", "失败数", "成功率(%)", "平均耗时(ms)"])
    
    # 应用表头样式
    for cell in ws2[1]:
        cell.fill = header_fill
        cell.font = header_font
    
    for point in trends['data_points']:
        ws2.append([
            point['time'],
            point['total'],
            point['success'],
            point['failed'],
            point['success_rate'],
            point['avg_duration_ms']
        ])
    
    # ========== Sheet3: 按数据库统计 ==========
    ws3 = wb.create_sheet("按数据库统计")
    ws3.append(["数据库", "同步数", "成功率(%)", "平均耗时(ms)", "同步记录数"])
    
    for cell in ws3[1]:
        cell.fill = header_fill
        cell.font = header_font
    
    for db_stat in overview['by_database']:
        ws3.append([
            db_stat['database'],
            db_stat['sync_count'],
            db_stat['success_rate'],
            db_stat['avg_duration'],
            db_stat['records_synced']
        ])
    
    # 调整列宽
    for ws in [ws1, ws2, ws3]:
        for column in ws.columns:
            max_length = max(len(str(cell.value or "")) for cell in column)
            ws.column_dimensions[column[0].column_letter].width = max_length + 2
    
    # 保存到BytesIO
    output = BytesIO()
    wb.save(output)
    output.seek(0)
    
    filename = f"sync_statistics_{datetime.now().strftime('%Y%m%d_%H%M%S')}.xlsx"
    
    return StreamingResponse(
        output,
        media_type="application/vnd.openxmlformats-officedocument.spreadsheetml.sheet",
        headers={"Content-Disposition": f"attachment; filename={filename}"}
    )
```

## 8.4 本章小结

本章详细介绍了统计报表与数据可视化的设计与实现，涵盖同步监控统计、业务数据统计、前端可视化三个层面。

**同步监控统计（8.1节）**实现了多维度的同步性能分析。概览统计（8.1.1）通过6个维度（总体、按数据库、按表、按操作、延迟、健康度）提供全局视图，使用复杂的SQLAlchemy聚合查询（COUNT、SUM、AVG、CASE、GROUP BY）计算统计指标。性能趋势分析（8.1.2）按小时/天/周粒度统计时间序列数据，支持峰值谷值识别、趋势拟合、异常检测，生成适合前端折线图渲染的数据格式。冲突统计（8.1.3）分析更新冲突、删除冲突、唯一约束冲突三种类型，统计冲突率、解决策略分布、解决耗时，为优化同步策略提供数据支撑。

**业务数据统计（8.2节）**面向运营决策提供关键业务指标。交易统计（8.2.1）计算总交易金额、平均客单价、完成率、取消率等指标，按时间、分类、支付方式、用户分层多维度分析，自动生成业务洞察（如完成率健康度判断、增长趋势分析、分类集中度评估）。用户活跃度分析（8.2.2）统计DAU/WAU/MAU、计算用户粘性（DAU/MAU比值）、分析留存率（次日/7日/30日留存），使用Cohort Analysis（队列分析）跟踪不同时期注册用户的留存曲线，按活跃度将用户分为核心/活跃/普通/偶发四个层级。

**数据可视化（8.3节）**将统计数据转化为直观的图表和仪表盘。前端图表组件（8.3.1）基于ECharts实现，封装为Vue组件支持props配置和响应式更新，同步性能趋势图使用多Y轴展示同步次数、成功率、耗时三个指标，支持数据点标记（峰值/谷值）、阈值线（健康线/性能线）、区域缩放、导出PNG等交互功能。实时监控面板（8.3.2）通过WebSocket接收服务端推送的实时指标，展示指标卡片（同步状态、业务数据、系统资源）、嵌入多个图表组件、维护告警历史列表，实现异常自动检测和桌面通知。数据导出功能（8.3.3）使用openpyxl生成多Sheet Excel文件，包含概览统计、时序趋势、分类统计等内容，通过StreamingResponse返回文件流供前端下载。

## 8.4 报表导出

### 8.4.1 Excel报表导出

```python
from openpyxl import Workbook
from openpyxl.styles import Font, Alignment, PatternFill
from io import BytesIO

@router.get("/reports/sync/export")
async def export_sync_report(
    start_date: date,
    end_date: date,
    current_user: User = Depends(get_current_user)
):
    """导出同步报表（Excel格式）"""
    
    # 查询数据
    with db_manager.session_scope("mysql") as session:
        sync_logs = session.execute(
            select(SyncLog)
            .where(
                SyncLog.started_at >= start_date,
                SyncLog.started_at <= end_date
            )
            .order_by(SyncLog.started_at.desc())
        ).scalars().all()
    
    # 创建工作簿
    wb = Workbook()
    ws = wb.active
    ws.title = "同步日志"
    
    # 设置表头
    headers = ["ID", "表名", "源库", "目标库", "状态", "记录数", "耗时(ms)", "开始时间"]
    ws.append(headers)
    
    # 设置表头样式
    header_fill = PatternFill(start_color="366092", end_color="366092", fill_type="solid")
    header_font = Font(color="FFFFFF", bold=True)
    
    for cell in ws[1]:
        cell.fill = header_fill
        cell.font = header_font
        cell.alignment = Alignment(horizontal="center")
    
    # 填充数据
    for log in sync_logs:
        ws.append([
            log.id,
            log.table_name,
            log.source_db,
            log.target_db,
            log.status,
            log.records_synced,
            log.duration_ms,
            log.started_at.strftime("%Y-%m-%d %H:%M:%S")
        ])
    
    # 调整列宽
    ws.column_dimensions['A'].width = 8
    ws.column_dimensions['B'].width = 20
    ws.column_dimensions['C'].width = 12
    ws.column_dimensions['D'].width = 12
    ws.column_dimensions['E'].width = 10
    ws.column_dimensions['F'].width = 10
    ws.column_dimensions['G'].width = 12
    ws.column_dimensions['H'].width = 20
    
    # 保存到内存
    output = BytesIO()
    wb.save(output)
    output.seek(0)
    
    # 返回文件
    return StreamingResponse(
        output,
        media_type="application/vnd.openxmlformats-officedocument.spreadsheetml.sheet",
        headers={
            "Content-Disposition": f"attachment; filename=sync_report_{start_date}_{end_date}.xlsx"
        }
    )
```
