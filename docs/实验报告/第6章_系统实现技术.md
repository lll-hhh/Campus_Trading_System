# 第6章 系统实现技术

## 6.1 后端架构实现

### 6.1.1 FastAPI框架应用

FastAPI是本系统后端的核心框架，它基于Python 3.7+的类型提示和异步编程特性，提供了高性能、易用性和自动文档生成等优势。本节详细介绍FastAPI在项目中的应用，包括项目结构设计、应用初始化、中间件配置、依赖注入系统等关键技术实现。选择FastAPI而非Flask、Django的原因在于：第一，FastAPI的异步特性能显著提升并发处理能力，在本系统的多数据库同步场景中，需要同时处理大量的数据库I/O操作，异步框架可以避免线程阻塞，提升系统吞吐量；第二，FastAPI基于Pydantic的数据验证机制提供了强大的类型安全保障，能在编译时捕获大量潜在错误；第三，FastAPI自动生成的OpenAPI文档（Swagger UI和Redoc）极大地方便了前后端联调和第三方集成；第四，FastAPI的依赖注入系统设计优雅，能够有效实现代码解耦和横切关注点的集中管理。

#### 项目结构设计

后端采用模块化的项目结构，按照功能域（Domain）划分为多个独立的服务模块，每个模块负责特定的业务功能。这种架构设计遵循了单一职责原则和高内聚低耦合原则，便于团队协作开发和后期维护扩展。核心结构包括：

**apps目录（应用服务层）：** 存放所有业务服务模块，每个子目录是一个独立的服务单元，包含完整的路由、业务逻辑、数据模型和单元测试。各服务模块之间通过定义清晰的API接口进行通信，避免直接的模块间依赖，降低耦合度。具体模块如下：

- **api_gateway（API网关）**：统一的API入口点，负责路由分发、请求验证、负载均衡、限流降级等网关功能。所有前端请求首先到达网关，网关根据路由规则转发到相应的服务模块。网关还实现了请求聚合（Aggregation）功能，将多个微服务的响应合并为一个响应返回给前端，减少网络往返次数。网关使用Redis实现了基于令牌桶算法的限流机制，防止恶意请求和流量突增导致的系统过载。

- **trade_service（交易服务）**：处理交易相关的所有业务逻辑，包括交易订单创建、支付确认、发货通知、收货确认、交易评价、售后处理等完整的交易流程。交易服务管理复杂的交易状态机（pending→contacted→meeting→completed/cancelled），确保状态转换的合法性。交易服务还实现了交易超时自动取消机制，使用APScheduler定时任务检查超时订单并自动取消，释放被锁定的零件库存。交易数据涉及金额结算，因此特别注重事务一致性和数据安全，所有涉及金额变更的操作都使用数据库事务保护。

- **inventory_service（零件服务）**：管理零件的完整生命周期，包括零件发布、编辑、上下架、删除、搜索、分类浏览、推荐展示等功能。零件服务是系统的核心业务模块之一，处理的数据量最大。零件发布时进行图片上传（支持OSS对象存储）、内容审核（敏感词过滤、图片鉴黄）、价格合理性检查（防止恶意定价）。零件搜索功能集成了Elasticsearch全文检索引擎，支持关键词搜索、分类筛选、价格区间筛选、排序（价格、时间、热度）等多维度查询，搜索响应时间控制在100ms以内。零件推荐使用协同过滤算法，根据用户的浏览历史和收藏记录推荐相似零件，提升用户体验和成交转化率。


- **ai_service（AI服务）**：提供人工智能相关功能，增强系统的智能化水平。主要功能包括：1）智能定价：基于历史成交数据和零件属性，使用机器学习模型（随机森林回归）预测零件的合理定价区间，辅助供应商定价决策；2）零件推荐：使用协同过滤算法（基于用户的CF和基于零件的CF结合）为用户推荐感兴趣的零件，提升用户停留时间和成交率；3）图片识别：集成腾讯云/阿里云的图像识别API，自动识别零件图片中的零件类别，辅助供应商填写零件信息，同时进行图片鉴黄审核；4）敏感词检测：对零件标题、描述、评论、私信等用户生成内容进行敏感词过滤，包含违禁品关键词库和DFA算法实现的高效匹配；5）异常检测：使用孤立森林算法检测异常交易行为（如刷单、欺诈），生成风险预警。

- **monitoring_service（监控服务）**：系统监控和数据统计模块，负责收集、存储、分析和展示系统运行指标。监控指标包括：1）性能指标：API响应时间（P50/P95/P99）、QPS（每秒请求数）、数据库查询耗时、缓存命中率等；2）业务指标：用户注册数、零件发布数、交易订单数、交易成功率、用户活跃度等；3）资源指标：CPU使用率、内存占用、磁盘IO、网络带宽等；4）错误指标：HTTP错误率（4xx/5xx）、异常堆栈、数据库死锁、同步冲突等。监控数据通过Prometheus采集，使用Grafana构建可视化大屏，支持告警通知（邮件、短信、钉钉机器人），帮助运维团队及时发现和处理故障。

**core目录（核心基础设施层）：** 存放核心基础设施代码，被所有服务模块共享使用，提供统一的技术能力。核心模块不包含业务逻辑，只提供技术基础设施，符合分层架构的原则。

- **database.py（数据库管理）**：封装了多数据库连接管理、会话管理、事务管理等核心功能。本系统需要同时支持MySQL、PostgreSQL、MariaDB、SQLite四种数据库，database.py提供统一的数据库访问接口，屏蔽不同数据库的差异。核心功能包括：1）连接池管理：使用SQLAlchemy的连接池机制，预创建一定数量的数据库连接（pool_size=5-20），避免每次请求都创建新连接的开销，连接池大小根据并发量动态调整；2）会话管理：提供session_scope上下文管理器，自动处理会话的开启、提交、回滚和关闭，简化数据库操作代码；3）主从读写分离：配置master-slave架构，写操作路由到主库，读操作路由到从库，降低主库压力，提升查询性能；4）自动重连：检测数据库连接断开（网络波动、数据库重启），自动重建连接，提升系统可用性；5）SQL日志记录：记录所有SQL语句及其执行时间，方便性能分析和慢查询优化。

- **redis_client.py（Redis客户端）**：封装Redis操作接口，提供缓存、分布式锁、消息队列、计数器等功能。Redis在系统中扮演多重角色：1）缓存层：缓存热点数据（如零件详情、用户信息、分类列表），减少数据库查询压力，提升响应速度，缓存采用LRU淘汰策略，TTL设置为5-60分钟不等；2）分布式锁：使用Redis的SETNX命令实现分布式锁，解决分布式环境下的并发控制问题（如防止超卖、防止重复提交），锁带有过期时间避免死锁；3）消息队列：使用Redis Streams作为同步事件的消息队列，生产者发布数据库变更事件，消费者（同步worker）订阅并处理事件，支持消息持久化和消费组机制；4）计数器：实现零件浏览量、点赞数、收藏数等实时计数，使用INCR命令原子递增，定期批量刷新到数据库；5）限流器：使用令牌桶算法实现API限流，防止恶意请求，保护系统稳定性。Redis客户端支持Redis Cluster集群模式，提供高可用和水平扩展能力。

- **security.py（安全认证）**：实现系统的安全认证和授权机制，保护用户数据和API接口安全。主要功能包括：1）JWT认证：采用JWT（JSON Web Token）实现无状态身份认证，Token包含用户ID、角色、权限列表等信息，使用HS256算法签名防止篡改，Token有效期30天，支持刷新机制；2）密码加密：使用bcrypt算法对用户密码进行哈希存储，bcrypt自带盐值（salt）且计算成本可配置，有效防止彩虹表攻击和暴力破解；3）RBAC权限验证：基于角色的访问控制模型，用户关联角色，角色关联权限，通过中间件检查用户是否拥有访问资源所需的权限，支持细粒度的权限控制（如items:read、items:write、items:delete）；4）CSRF防护：为状态变更操作（POST、PUT、DELETE）生成CSRF Token，验证Token有效性，防止跨站请求伪造攻击；5）XSS过滤：对用户输入的文本内容进行HTML转义，过滤危险标签和脚本，防止跨站脚本攻击；6）SQL注入防护：使用SQLAlchemy的参数化查询，禁止直接拼接SQL字符串，防止SQL注入漏洞。

- **config.py（配置管理）**：统一的配置管理模块，负责从多种来源加载配置并提供全局访问接口。配置来源包括：1）环境变量（优先级最高）：从操作系统环境变量读取敏感配置（如数据库密码、API密钥），适合生产环境；2）配置文件：从config.yaml或.env文件读取配置，适合开发和测试环境；3）默认值：代码中定义的默认配置，确保即使没有外部配置也能运行。config.py使用Pydantic的BaseSettings实现配置验证，确保配置项的类型和格式正确，支持配置热更新（监听配置文件变化，重新加载配置而不重启应用）。配置项包括：数据库连接字符串、Redis地址、JWT密钥、API密钥（对象存储、第三方服务）、日志级别、CORS白名单等。

**alembic目录（数据库迁移工具）：** Alembic是SQLAlchemy的数据库迁移工具，管理数据库schema的版本演进。在开发过程中，数据库结构会不断变化（添加表、修改字段、创建索引等），Alembic能够记录每次变更，并提供升级（upgrade）和回滚（downgrade）功能。alembic/versions目录存放迁移脚本，每个脚本对应一次schema变更，包含upgrade()函数（执行变更）和downgrade()函数（回滚变更）。使用Alembic的好处是：1）版本控制：数据库schema的每次变更都有记录，可追溯历史；2）环境一致性：开发、测试、生产环境可以执行相同的迁移脚本，确保schema一致；3）团队协作：多人开发时避免schema冲突，通过迁移脚本合并变更；4）安全回滚：出现问题时可以快速回滚到之前的版本。Alembic还支持自动生成迁移脚本（通过对比模型定义和数据库现状），减少手动编写SQL的工作量。

**tests目录（测试用例）：** 包含单元测试和集成测试代码，使用pytest测试框架。测试覆盖率目标>80%，每次代码提交都会自动运行测试（CI/CD流水线），确保代码质量。测试目录按照源代码结构组织：test_api目录测试API接口，test_services目录测试业务服务，test_core目录测试核心模块。测试使用了大量的fixture（pytest的测试准备机制）来准备测试数据和模拟依赖（如Mock数据库、Mock Redis），提高测试的独立性和可重复性。集成测试使用Docker Compose启动完整的测试环境（包括数据库、Redis、应用服务），模拟真实运行环境，确保各模块协同工作正常。

#### FastAPI应用初始化

FastAPI应用的初始化过程是整个系统启动的核心环节，包括配置加载、资源初始化、中间件注册、路由配置等关键步骤。本系统采用了FastAPI 0.104+引入的lifespan事件管理机制，优雅地处理应用的启动和关闭流程，确保资源的正确初始化和清理。相比传统的startup/shutdown事件处理器，lifespan机制使用Python的async context manager（异步上下文管理器）实现，代码更简洁，错误处理更完善，是FastAPI推荐的最佳实践。

**生命周期管理（Lifespan）原理和实现：**

lifespan函数使用`@asynccontextmanager`装饰器定义，这是Python标准库asyncio提供的异步上下文管理器工具。函数体被`yield`语句分为两部分：yield之前的代码在应用启动时执行（startup phase），yield之后的代码在应用关闭时执行（shutdown phase）。这种设计的优势在于：第一，资源初始化和清理代码写在一起，逻辑关联性强，不易遗漏清理步骤；第二，异常处理简单，如果启动阶段出现异常，应用不会进入运行状态，关闭阶段的代码不会执行，避免清理不存在的资源；第三，支持多层嵌套，可以组合多个lifespan管理器实现模块化的资源管理。

**启动阶段（Startup Phase）核心任务：**

1. **数据库连接池初始化**：调用database manager的initialize()方法为MySQL、PostgreSQL、MariaDB、SQLite四种数据库分别建立连接池。连接池参数配置：pool_size=5（最小连接数），max_overflow=10（最大溢出连接数），pool_timeout=30秒（获取连接超时），pool_recycle=3600秒（连接回收时间，防止MySQL的wait_timeout问题）。连接池的好处是避免每次请求都创建新连接的开销（TCP三次握手+数据库认证需要10-50ms），连接复用可以将数据库连接时间降低到<1ms，显著提升系统性能。初始化过程中还会执行数据库健康检查（SELECT 1查询），确保数据库可用，如果任一数据库连接失败，应用启动失败并记录错误日志，方便运维人员排查问题。

2. **Redis连接建立**：连接到Redis Cluster集群，建立客户端连接。Redis配置使用哨兵模式（Sentinel）实现高可用，当Master节点故障时自动切换到Slave节点。Redis连接参数：decode_responses=True（自动解码byte为str），max_connections=50（连接池大小），socket_timeout=5秒（命令超时），socket_keepalive=True（TCP长连接），retry_on_timeout=True（超时重试）。初始化后执行PING命令验证连接可用性，并设置连接测试key确保读写权限正常。

3. **同步Worker启动**：启动后台Worker进程，负责监听数据库变更事件并执行同步任务。Worker数量根据CPU核心数配置（通常为CPU核心数的1-2倍），每个Worker是一个独立的asyncio Task，从Redis Streams消息队列中消费同步事件。Worker启动时注册消费组（Consumer Group），支持负载均衡和故障转移：多个Worker自动分配消息，一个Worker故障后其他Worker接管未完成的消息。Worker还会启动心跳机制，每30秒向Redis写入心跳时间戳，监控服务通过检查心跳判断Worker状态，及时发现故障Worker。

4. **定时任务调度器启动**：启动APScheduler定时任务调度器，管理系统的周期性任务。定时任务包括：数据备份任务（每天凌晨3点执行，导出数据库到备份文件）；过期数据清理任务（每小时执行，清理超过30天的临时数据、过期日志）；统计报表生成任务（每天凌晨1点执行，生成昨日的业务统计报表）；缓存预热任务（每天早上7点执行，提前加载热门零件到Redis缓存，避免高峰期缓存击穿）。调度器使用Cron表达式配置触发时间，支持任务并发控制、失败重试、错过任务补偿等高级功能。

5. **AI模型预加载**：加载机器学习模型文件到内存，避免首次请求时加载模型导致的响应延迟。预加载的模型包括：零件定价模型（随机森林回归模型，pkl文件约5MB），推荐模型（协同过滤模型，矩阵分解结果约20MB），敏感词词典（Trie树结构，包含10万+敏感词）。模型加载到内存后，预测请求可以在10ms内完成，如果按需加载则首次请求需要500ms+，严重影响用户体验。模型加载使用多进程加速，充分利用多核CPU。

**关闭阶段（Shutdown Phase）核心任务：**

1. **优雅关闭（Graceful Shutdown）**：在开始关闭资源之前，等待1秒钟，给正在处理的HTTP请求一点时间完成。这个等待时间可以根据实际情况调整（通常设置为请求的P95响应时间），确保大部分请求能够正常完成，避免强制中断导致的数据不一致或前端报错。如果有长时间运行的请求（如大文件上传、复杂报表生成），可以配置更长的等待时间或使用任务队列异步处理。

2. **数据库连接池关闭**：调用database manager的close_all()方法，关闭所有数据库的连接池。关闭过程包括：等待所有活跃连接完成当前事务；关闭所有空闲连接；释放连接池占用的内存和文件描述符。正确关闭连接池可以避免数据库端的连接泄漏（数据库持续维护已断开的连接，消耗资源），确保数据库在应用重启后能够立即接受新连接。

3. **Redis连接关闭**：断开Redis客户端连接，释放网络socket和内存缓冲区。Redis客户端关闭前会将缓冲区中未发送的命令刷新到服务器，确保数据不丢失（如INCR计数、SET缓存等操作）。

4. **定时任务停止**：关闭APScheduler调度器，停止所有定时任务。调度器关闭时会等待正在执行的任务完成（wait=True参数），避免任务中断导致的数据不完整。如果有长时间运行的任务，可以设置最大等待时间（如30秒），超时后强制终止。

5. **状态保存**：将系统运行状态持久化到文件或数据库，包括：未完成的同步任务列表（下次启动时继续执行）；应用统计数据（请求总数、错误总数等，用于生成完整的运行报告）；临时数据清理标记（标记哪些数据可以安全删除）。状态保存使用事务保护，确保原子性。

**中间件配置（Middleware Stack）：**

FastAPI支持多层中间件，中间件按照添加顺序依次执行，形成"洋葱模型"：请求从外层中间件逐层传递到内层，响应从内层中间件逐层返回到外层。每个中间件可以在请求到达路由处理函数之前进行预处理（如认证、日志记录），在路由处理函数返回之后进行后处理（如响应压缩、添加Header）。本系统配置了以下中间件：

**1. CORS中间件（CORSMiddleware）：**

CORS（跨域资源共享）中间件允许前端JavaScript跨域访问后端API，解决浏览器同源策略限制。配置参数详解：
- `allow_origins`：允许访问的前端域名列表，包括开发环境（http://localhost:5173是Vite默认端口，http://localhost:3000是备用端口）和生产环境域名（https://campus-trade.example.com）。使用白名单而非`allow_origins=["*"]`是为了安全性，防止恶意网站跨域调用API。
- `allow_credentials=True`：允许前端携带凭证（Cookies、Authorization Header），这对于JWT认证是必需的，因为JWT Token通常存储在localStorage或Cookie中。
- `allow_methods=["*"]`：允许所有HTTP方法（GET、POST、PUT、DELETE、PATCH、OPTIONS等），简化配置。如果需要更严格的安全控制，可以明确指定允许的方法列表。
- `allow_headers=["*"]`：允许所有自定义请求头，包括Authorization、Content-Type、X-Requested-With等。前端使用Axios等HTTP库时经常需要自定义Header，通配符配置避免逐个添加。

CORS中间件的工作原理：浏览器发送跨域请求时，首先发送OPTIONS预检请求（Preflight Request），询问服务器是否允许跨域；服务器返回允许的域名、方法、Header后，浏览器才发送真正的请求。CORS中间件自动处理OPTIONS请求，返回正确的CORS响应头，简化了跨域配置。

**2. Gzip压缩中间件（GZipMiddleware）：**

Gzip中间件自动压缩HTTP响应体，减少网络传输时间，提升用户体验。配置参数`minimum_size=1000`表示只压缩大于1KB的响应，因为小响应压缩收益不大，压缩过程还有CPU开销，得不偿失。Gzip压缩对文本数据（JSON、HTML、CSS、JavaScript）效果显著，压缩比通常达到70-80%，即100KB的JSON响应压缩后只有20-30KB，在慢速网络环境下提升明显。Gzip压缩对已压缩的数据（如JPEG图片、视频）无效，中间件会自动检测Content-Type，跳过图片、视频等二进制数据。压缩增加服务器CPU负担约5-10%，但网络传输时间减少50%+，总体性能提升30-50%，是性价比极高的优化手段。

**3. 请求日志中间件（自定义中间件）：**

记录每个HTTP请求的详细信息，用于性能分析、问题排查、安全审计。记录的信息包括：
- 请求方法（GET/POST/PUT/DELETE等）和路径（/api/items/123）
- 查询参数（?page=1&page_size=20）和请求体（JSON数据，敏感字段如密码需要脱敏）
- 客户端IP地址（从request.client.host获取，如果有反向代理需要从X-Forwarded-For Header提取真实IP）
- 响应状态码（200成功、400客户端错误、500服务器错误）
- 处理耗时（从请求到达到响应返回的时间，单位毫秒）
- User-Agent（浏览器类型和版本，用于统计用户设备分布）

处理耗时通过`time.time()`计算：请求到达时记录start_time，响应返回时计算`(time.time() - start_time) * 1000`得到毫秒数。耗时添加到响应头`X-Process-Time`，前端可以读取这个Header展示加载时间，或者用于前端性能监控。日志级别根据状态码区分：状态码>=400记录为ERROR级别（方便过滤错误日志），状态码<400记录为INFO级别（正常日志）。日志输出到ELK（Elasticsearch+Logstash+Kibana）系统，支持全文搜索、聚合统计、可视化分析，快速定位慢接口、高频错误、异常IP等问题。

**4. 全局异常处理器（Exception Handler）：**

捕获所有未处理的异常，防止异常信息泄漏到客户端，统一返回友好的错误提示。如果不配置全局异常处理器，Python异常会被FastAPI默认处理器捕获并返回包含异常堆栈的JSON响应，暴露内部实现细节（如文件路径、数据库结构、第三方库版本等），可能被攻击者利用。全局异常处理器的职责：第一，记录异常详情（包含完整堆栈、请求上下文）到日志系统，日志包含exc_info=True参数会自动记录完整的异常堆栈，方便开发人员排查问题；第二，返回统一的错误响应（只包含错误代码、友好提示，不包含技术细节），保护系统安全；第三，对不同类型的异常返回不同的状态码和错误信息，如ValidationError返回400，PermissionError返回403，NotFoundError返回404，DatabaseError返回500等，遵循HTTP语义规范。

全局异常处理器还可以集成错误监控服务（如Sentry），自动上报生产环境的异常，包含完整的上下文信息（请求参数、用户信息、服务器状态等），帮助开发团队快速发现和修复线上问题。

```python
    import uuid
    request_id = str(uuid.uuid4())
    request.state.request_id = request_id
    
    # 记录请求到达时间
    start_time = time.time()
    client_ip = request.client.host
    
    # 提取User-Agent
    user_agent = request.headers.get("user-agent", "unknown")
    
    # 处理请求（执行后续中间件和路由处理函数）
    response = await call_next(request)
    
    # 计算处理耗时（毫秒，保留2位小数）
    process_time = (time.time() - start_time) * 1000
    
    # 添加响应头（前端可读取）
    response.headers["X-Process-Time"] = f"{process_time:.2f}ms"
    response.headers["X-Request-ID"] = request_id
    
    # 根据状态码选择日志级别
    log_level = logging.ERROR if response.status_code >= 400 else logging.INFO
    
    # 记录日志（结构化日志，方便ELK解析）
    logger.log(
        log_level,
        f"HTTP Request",
        extra={
            "request_id": request_id,
            "client_ip": client_ip,
            "method": request.method,
            "path": request.url.path,
            "query_params": str(request.query_params),
            "status_code": response.status_code,
            "process_time_ms": round(process_time, 2),
            "user_agent": user_agent,
        }
    )
    
    # 慢请求告警（处理时间 > 1秒）
    if process_time > 1000:
        logger.warning(
            f"Slow request detected: {request.method} {request.url.path} - {process_time:.2f}ms",
            extra={"request_id": request_id}
        )
    
    return response
```

#### 依赖注入系统

FastAPI的依赖注入（Dependency Injection）系统是其核心特性之一,允许声明式地定义函数依赖关系,自动解析和注入依赖项。本系统充分利用依赖注入实现了身份认证、权限验证、数据库会话管理、参数验证等横切关注点,代码简洁且易于测试。依赖注入的优势包括:第一,代码复用性高,同一个依赖可以被多个路由函数使用,避免重复代码;第二,关注点分离,业务逻辑和基础设施代码解耦,路由处理函数只关注核心业务;第三,易于测试,可以Mock依赖项进行单元测试;第四,类型安全,IDE可以提供完整的代码提示和类型检查。

**身份认证依赖（get_current_user）实现原理:**

get_current_user依赖函数负责从HTTP请求中提取并验证用户身份,是整个系统安全认证的核心。工作流程分为五个步骤:

1. **提取JWT令牌:** 使用FastAPI的HTTPBearer安全方案从请求的Authorization Header中提取Bearer Token。Header格式为`Authorization: Bearer <token>`,FastAPI自动解析并提取token部分。HTTPBearer类会自动处理Header格式验证,如果Header不存在或格式错误,自动返回401 Unauthorized响应,无需手动检查。

2. **解码JWT令牌:** 使用`python-jose`库的jwt.decode()函数解码Token。解码需要三个参数:token字符串、SECRET_KEY密钥、签名算法列表。系统使用HS256(HMAC-SHA256)算法签名,密钥从环境变量读取(生产环境存储在密钥管理服务),长度至少32字节确保安全性。解码过程会验证Token的签名是否正确(防止篡改)、是否过期(exp字段)、是否为合法Token。如果验证失败,抛出JWTError异常,捕获后返回401响应提示"Could not validate credentials"。

3. **提取用户ID:** 从JWT payload中提取sub(subject)字段,这是JWT标准字段用于存储主体标识。本系统在sub字段存储用户ID,payload还可能包含iat(签发时间)、exp(过期时间)、role(用户角色)等信息。如果sub字段不存在,说明Token格式错误,返回401响应。

4. **数据库查询用户:** 使用database manager的session_scope上下文管理器获取数据库会话,支持指定数据库(默认mysql)实现多数据库切换。使用`session.get(User, user_id)`查询用户,get()方法是SQLAlchemy的主键查询API,比filter()效率更高(直接走主键索引),时间复杂度O(log n)。如果用户不存在,说明Token已过期(用户被删除),返回404响应提示"User not found - Token may be outdated"。

5. **检查用户状态:** 验证用户的status字段,只有status="active"的用户可以访问系统。如果用户被封禁(status="banned"),返回403响应提示"User account has been banned";如果用户未激活(status="inactive"),返回403响应提示账户未激活。这种状态检查机制允许管理员封禁用户后立即生效,无需等待Token过期。

这个依赖被大量路由处理函数使用,通过`current_user: User = Depends(get_current_user)`注入,避免在每个路由函数中重复认证代码,符合DRY原则。依赖注入自动处理异常,如果get_current_user抛出HTTPException,FastAPI自动返回相应的错误响应,路由处理函数不会执行,保证安全性。

**权限验证依赖（require_permission）高阶函数设计:**

require_permission是一个高阶函数(返回函数的函数),实现了参数化的依赖注入。使用高阶函数的原因是FastAPI的依赖函数本身不能接受参数,但我们需要为不同的路由指定不同的权限代码,高阶函数解决了这个问题。

设计思路:require_permission(permission_code)返回一个依赖函数permission_checker,这个依赖函数通过闭包捕获了permission_code参数,在运行时检查用户是否拥有该权限。使用示例:

```python
# 删除零件需要items:delete权限
@router.delete("/items/{item_id}")
async def delete_item(
    item_id: int,
    current_user: User = Depends(require_permission("items:delete"))
):
    # 只有拥有items:delete权限的用户才能执行到这里
    ...
```

权限检查基于RBAC(基于角色的访问控制)模型,数据模型为:用户(User) → 用户角色关联(UserRole) → 角色(Role) → 角色权限关联(RolePermission) → 权限(Permission)。查询逻辑通过多表JOIN获取用户的所有权限:

```sql
SELECT permissions.* 
FROM permissions
JOIN role_permissions ON permissions.id = role_permissions.permission_id
JOIN user_roles ON role_permissions.role_id = user_roles.role_id  
WHERE user_roles.user_id = ? AND permissions.permission_code = ?
```

如果查询结果为空,说明用户不拥有该权限,抛出403 Forbidden异常。这种设计将权限控制逻辑集中管理,修改权限规则时只需调整数据库数据(通过管理后台),无需修改代码重新部署,实现了权限配置的动态化。

系统还实现了超级管理员机制:User表的is_superuser字段为True的用户自动跳过权限检查,拥有所有权限。这简化了超级管理员的权限配置,避免为超级管理员分配所有权限记录。

**数据库会话依赖（get_db_session）工厂函数:**

get_db_session是一个工厂函数,返回特定数据库的会话依赖。使用yield关键字实现上下文管理,确保会话的正确清理:

```python
def get_db_session(db_name: str = "mysql"):
    with db_manager.session_scope(db_name) as session:
        yield session
    # session自动提交或回滚(出现异常),然后关闭
```

session_scope上下文管理器的实现:
- __enter__: 创建新的数据库会话(Session)
- yield: 返回会话供路由处理函数使用
- __exit__: 如果无异常则commit提交事务,如果有异常则rollback回滚,最后close关闭会话释放资源

这种设计的好处:第一,自动事务管理,无需手动commit/rollback,减少遗漏;第二,异常安全,即使路由处理函数抛出异常,会话也能正确回滚和关闭,避免数据不一致和连接泄漏;第三,连接复用,关闭会话后连接返回连接池,下次请求复用,提升性能。

支持多数据库场景,通过参数指定目标数据库(mysql/postgres/mariadb/sqlite),灵活切换数据源:

```python
@router.get("/items")
async def list_items(
    db: Session = Depends(get_db_session("postgres"))  # 使用PostgreSQL
):
    items = db.execute(select(Item).limit(10)).scalars().all()
    return items
```

**分页参数依赖（PaginationParams）类设计:**

PaginationParams是一个依赖类(类的__init__方法作为依赖函数),统一处理分页查询参数。FastAPI支持类作为依赖,自动调用__init__方法并注入参数。设计要点:

1. **参数验证:** 使用FastAPI的Query验证器定义参数约束:
   - page: ge=1(大于等于1),页码从1开始
   - page_size: ge=1(至少1条), le=100(最多100条),防止单次查询数据量过大影响性能

2. **默认值:** page默认1,page_size默认20,符合多数场景需求,调用方可以省略参数

3. **计算offset和limit:** __init__方法自动计算SQL分页所需的offset和limit值:
   - offset = (page - 1) * page_size: 跳过的记录数
   - limit = page_size: 查询的记录数
   
   例如第3页每页20条,offset=40,limit=20,查询第41-60条记录

4. **to_dict方法:** 将分页参数转换为字典,方便包含在API响应中:
   ```json
   {
     "data": [...],
     "pagination": {
       "page": 3,
       "page_size": 20,
       "offset": 40,
       "limit": 20
     }
   }
   ```

使用示例:

```python
@router.get("/items")
async def list_items(
    pagination: PaginationParams = Depends()  # 自动注入分页参数
):
    query = select(Item).limit(pagination.limit).offset(pagination.offset)
    items = db.execute(query).scalars().all()
    
    # 计算总数(用于前端分页组件)
    total = db.execute(select(func.count()).select_from(Item)).scalar()
    
    return {
        "data": items,
        "pagination": {
            **pagination.to_dict(),
            "total": total,
            "total_pages": (total + pagination.page_size - 1) // pagination.page_size
        }
    }
```

所有列表查询接口都可以复用这个依赖,保证分页行为的一致性,避免不同接口的分页实现不一致导致的前端适配问题。

```python
# apps/api_gateway/dependencies.py
from fastapi import Depends, HTTPException, status, Query
from fastapi.security import HTTPBearer, HTTPAuthorizationCredentials
from jose import JWTError, jwt
from typing import Optional, Annotated
from sqlalchemy.orm import Session
from sqlalchemy import select
from core.config import settings
from core.database import db_manager
from apps.core.models import User, Permission, UserRole, RolePermission, Role

# HTTP Bearer认证方案（从Authorization header获取token）
# FastAPI安全工具,自动处理Header解析和格式验证
security = HTTPBearer()

# ============ 身份认证依赖 ============
async def get_current_user(
    credentials: HTTPAuthorizationCredentials = Depends(security),
    db_name: str = "mysql"
) -> User:
    """
    从JWT令牌获取当前登录用户
    
    工作流程:
    1. 从Authorization header提取Bearer token
    2. 验证JWT签名和过期时间
    3. 解码获取用户ID(存储在sub字段)
    4. 从数据库查询用户信息(支持多数据库)
    5. 检查用户状态(是否激活、是否封禁)
    
    依赖链:
    - HTTPBearer: 自动提取和验证Authorization Header格式
    - jwt.decode: 验证Token签名、过期时间
    - db_manager: 提供数据库会话
    
    Args:
        credentials: HTTP Bearer认证凭证(自动从header提取)
        db_name: 数据库名称(默认mysql,支持postgres/mariadb/sqlite)
    
    Returns:
        User: 当前登录的用户对象(ORM模型)
    
    Raises:
        HTTPException 401: 令牌无效或过期
            - JWT签名错误
            - Token已过期(exp字段)
            - sub字段缺失
        HTTPException 404: 用户不存在
            - 用户ID在数据库中不存在
            - Token已过期但未及时刷新
        HTTPException 403: 用户被封禁
            - status='banned': 账户被管理员封禁
            - status='inactive': 账户未激活
    
    使用示例:
        @router.get("/profile")
        async def get_profile(current_user: User = Depends(get_current_user)):
            return {"username": current_user.username, "email": current_user.email}
    """
    
    # 提取JWT令牌(HTTPBearer已验证Header格式)
    token = credentials.credentials
    
    try:
        # 解码JWT令牌
        # SECRET_KEY: 密钥,从环境变量读取,长度至少32字节
        # ALGORITHM: 签名算法,使用HS256(HMAC-SHA256)
        # jwt.decode会自动验证:
        #   - 签名是否正确(防止篡改)
        #   - 是否过期(exp字段,默认30天)
        #   - Token格式是否合法
        payload = jwt.decode(
            token, 
            settings.SECRET_KEY, 
            algorithms=[settings.ALGORITHM]
        )
        
        # 提取用户ID(JWT标准字段sub: subject主体标识)
        user_id: int = payload.get("sub")
        
        # sub字段缺失,Token格式错误
        if user_id is None:
            raise HTTPException(
                status_code=status.HTTP_401_UNAUTHORIZED,
                detail="Invalid authentication credentials - Missing user ID",
                headers={"WWW-Authenticate": "Bearer"},  # 提示客户端重新认证
            )
            
    except JWTError as e:
        # JWT解码失败(签名错误、过期、格式错误等)
        # 记录详细错误信息到日志(不返回给客户端,安全考虑)
        import logging
        logging.error(f"JWT decode failed: {e}")
        
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail=f"Could not validate credentials - Invalid token",
            headers={"WWW-Authenticate": "Bearer"},
        )
    
    # 从数据库查询用户(使用指定的数据库)
    # session_scope自动管理会话生命周期(commit/rollback/close)
    with db_manager.session_scope(db_name) as session:
        # 使用session.get()主键查询,比filter()效率更高
        # get()直接走主键索引,时间复杂度O(log n)
        user = session.get(User, user_id)
        
        # 用户不存在(可能被删除,或Token已过期)
        if user is None:
            raise HTTPException(
                status_code=status.HTTP_404_NOT_FOUND,
                detail="User not found - Token may be outdated, please login again"
            )
        
        # 检查用户状态 - 是否被封禁
        if user.status == "banned":
            raise HTTPException(
                status_code=status.HTTP_403_FORBIDDEN,
                detail="User account has been banned - Contact administrator"
            )
        
        # 检查用户状态 - 是否激活
        if user.status != "active":
            raise HTTPException(
                status_code=status.HTTP_403_FORBIDDEN,
                detail=f"User account is {user.status} - Please activate your account"
            )
    
    return user

# ============ 可选身份认证依赖 ============
async def get_current_user_optional(
    credentials: Optional[HTTPAuthorizationCredentials] = Depends(HTTPBearer(auto_error=False)),
    db_name: str = "mysql"
) -> Optional[User]:
    """
    可选的身份认证依赖
    
    与get_current_user的区别:
    - auto_error=False: Token不存在或无效时返回None而不抛出异常
    - 用于可选登录的接口(如零件列表,登录和未登录用户都能访问)

    - 零件列表: 未登录显示公开零件,登录后显示推荐零件

# ============ 权限验证依赖(高阶函数) ============
def require_permission(permission_code: str):
    """
    检查用户是否具有指定权限(工厂函数)
    
    返回一个依赖函数,该函数验证当前用户是否拥有指定的权限代码
    基于RBAC模型: 用户 → 角色 → 权限
    
    权限代码格式: "资源:操作"
    示例: items:read, items:write, items:delete, users:管理
    
    权限检查流程:
    1. 检查是否为超级管理员(跳过权限检查)
    2. 多表JOIN查询用户的所有权限
    3. 判断是否包含目标权限代码
    4. 无权限抛出403异常
    
    使用示例:
        @router.delete("/items/{item_id}")
        async def delete_item(
            item_id: int,
            current_user: User = Depends(require_permission("items:delete"))
        ):
            # 只有拥有items:delete权限的用户才能执行到这里
            ...
    
    Args:
        permission_code: 权限代码,格式为"资源:操作",如"items:delete"
    
    Returns:
        依赖函数: 检查权限并返回用户对象
    
    实现原理:
    - 高阶函数(返回函数的函数)实现参数化依赖
    - 通过闭包捕获permission_code参数
    - 依赖链: require_permission → permission_checker → get_current_user
    """
    
    async def permission_checker(
        current_user: User = Depends(get_current_user)
    ) -> User:
        """
        内部依赖函数: 验证当前用户是否拥有指定权限
        
        查询逻辑(多表JOIN):
        users → user_roles → roles → role_permissions → permissions
        
        SQL等价:
        SELECT permissions.* 
        FROM permissions
        JOIN role_permissions ON permissions.id = role_permissions.permission_id
        JOIN user_roles ON role_permissions.role_id = user_roles.role_id
        WHERE user_roles.user_id = ? AND permissions.permission_code = ?
        """
        
        # 超级管理员拥有所有权限,跳过检查
        # 简化超级管理员的权限配置
        if current_user.is_superuser:
            return current_user
        
        # 查询用户权限(多表JOIN)
        with db_manager.session_scope("mysql") as session:
            # SQLAlchemy查询构建器
            # join()自动根据外键关系进行JOIN
            has_permission = session.execute(
                select(Permission)
                .join(RolePermission, RolePermission.permission_id == Permission.id)
                .join(UserRole, UserRole.role_id == RolePermission.role_id)
                .where(UserRole.user_id == current_user.id)
                .where(Permission.permission_code == permission_code)
            ).scalar_one_or_none()
            
            # 权限不存在,返回403 Forbidden
            if not has_permission:
                raise HTTPException(
                    status_code=status.HTTP_403_FORBIDDEN,
                    detail=f"Permission denied: '{permission_code}' required"
                )
        
        return current_user
    
    return permission_checker

# ============ 管理员权限验证依赖 ============
async def require_admin(
    current_user: User = Depends(get_current_user)
) -> User:
    """
    验证用户是否为管理员
    
    检查用户角色:
    - is_superuser=True: 超级管理员
    - role包含'admin': 普通管理员

        async def approve_item(
            item_id: int,
            current_user: User = Depends(require_admin)
        ):
            # 只有管理员可以审核零件
            ...
    """
    if current_user.is_superuser:
        return current_user
    
    # 查询用户角色
    with db_manager.session_scope("mysql") as session:
        user_roles = session.execute(
            select(Role)
            .join(UserRole, UserRole.role_id == Role.id)
            .where(UserRole.user_id == current_user.id)
        ).scalars().all()
        
        # 检查是否有admin角色
        if any(role.role_name == "admin" for role in user_roles):
            return current_user
    
    raise HTTPException(
        status_code=status.HTTP_403_FORBIDDEN,
        detail="Administrator privileges required"
    )

# ============ 数据库会话依赖(工厂函数) ============
def get_db_session(db_name: str = "mysql"):
    """
    获取数据库会话(工厂函数)
    
    为每个请求创建独立的数据库会话,请求结束后自动提交或回滚
    使用yield实现上下文管理,确保会话正确关闭
    
    工作原理:
    1. __enter__: 创建新的数据库会话
    2. yield: 返回会话供路由使用
    3. __exit__: 
       - 无异常: commit提交事务
       - 有异常: rollback回滚事务
       - 最后: close关闭会话(连接返回连接池)
    
    Args:
        db_name: 数据库名称(mysql/postgres/mariadb/sqlite)
    
    Yields:
        Session: SQLAlchemy数据库会话对象
    
    使用示例:
        @router.get("/items")
        async def list_items(
            db: Session = Depends(get_db_session("postgres"))
        ):
            items = db.execute(select(Item).limit(10)).scalars().all()
            return items
    """
    with db_manager.session_scope(db_name) as session:
        yield session
    # session自动提交(无异常)或回滚(有异常),然后关闭

# ============ 分页参数依赖(类依赖) ============
class PaginationParams:
    """
    统一的分页参数依赖
    
    提供默认值、合法性验证、offset/limit计算
    所有列表查询接口可以复用,保证分页行为一致性
    
    参数:
    - page: 页码,从1开始,默认1
    - page_size: 每页数量,范围1-100,默认20
    
    计算属性:
    - offset: SQL OFFSET值,跳过的记录数 = (page-1) * page_size
    - limit: SQL LIMIT值,查询的记录数 = page_size
    
    使用示例:
        @router.get("/items")
        async def list_items(
            pagination: PaginationParams = Depends()
        ):
            query = select(Item).limit(pagination.limit).offset(pagination.offset)
            items = db.execute(query).scalars().all()
            
            return {
                "data": items,
                "pagination": pagination.to_dict()
            }
    """
    
    def __init__(
        self,
        page: Annotated[int, Query(ge=1, description="页码(从1开始)")] = 1,
        page_size: Annotated[int, Query(ge=1, le=100, description="每页数量(1-100)")] = 20
    ):
        """
        初始化分页参数
        
        FastAPI自动从查询参数提取page和page_size
        Query验证器确保参数合法性:
        - page >= 1: 页码最小为1
        - 1 <= page_size <= 100: 限制单次查询数量,防止性能问题
        
        计算offset和limit供SQL查询使用
        """
        self.page = page
        self.page_size = page_size
        self.offset = (page - 1) * page_size  # 计算SQL OFFSET
        self.limit = page_size                # 计算SQL LIMIT
    
    def to_dict(self) -> dict:
        """
        转换为字典(用于API响应)
        
        返回格式:
        {
            "page": 3,
            "page_size": 20,
            "offset": 40,
            "limit": 20
        }
        
        前端可以据此计算总页数:
        total_pages = ceil(total / page_size)
        """
        return {
            "page": self.page,
            "page_size": self.page_size,
            "offset": self.offset,
            "limit": self.limit
        }
    
    def add_total(self, total: int) -> dict:
        """
        添加总数信息
        
        Args:
            total: 记录总数
        
        Returns:
            包含总数和总页数的字典
        """
        return {
            **self.to_dict(),
            "total": total,
            "total_pages": (total + self.page_size - 1) // self.page_size  # 向上取整
        }

class SortParams:
    """
    统一的排序参数依赖
    
    参数:
    - sort_by: 排序字段(如'created_at', 'price', 'views')
    - order: 排序方向('asc'升序, 'desc'降序)
    
    使用示例:
        @router.get("/items")
        async def list_items(
            sort: SortParams = Depends()
        ):
            query = select(Item).order_by(sort.get_order_by())
            ...
    """
    
    def __init__(
        self,
        sort_by: Annotated[str, Query(description="排序字段")] = "created_at",
        order: Annotated[str, Query(regex="^(asc|desc)$", description="排序方向")] = "desc"
    ):
        self.sort_by = sort_by
        self.order = order
    
    def get_order_by(self, model):
        """
        生成SQLAlchemy排序表达式
        
        Args:
            model: ORM模型类
        
        Returns:
            SQLAlchemy排序表达式
        
        示例:
            sort.get_order_by(Item)  # Item.created_at.desc()
        """
        column = getattr(model, self.sort_by)
        return column.desc() if self.order == "desc" else column.asc()
```

```python
class DatabaseManager:
    """多数据库管理器"""
    
    def __init__(self):
        self.engines: Dict[str, Engine] = {}
        self.session_factories: Dict[str, sessionmaker] = {}
    
    def initialize(self):
        """初始化所有数据库连接"""
        
        # MySQL主库
        self.engines["mysql"] = create_engine(

            pool_size=20,
            max_overflow=10,
            pool_pre_ping=True,

        )
        
        # PostgreSQL
        self.engines["postgres"] = create_engine(
            settings.POSTGRES_URL,
            pool_size=10,
            max_overflow=5,
            pool_pre_ping=True
        )
        
        # MariaDB
        self.engines["mariadb"] = create_engine(
            settings.MARIADB_URL,
            pool_size=10,
            max_overflow=5,
            pool_pre_ping=True
        )
        
        # SQLite
        self.engines["sqlite"] = create_engine(
            settings.SQLITE_URL,
            connect_args={"check_same_thread": False}
        )
        
        # 创建会话工厂
        for db_name, engine in self.engines.items():
            self.session_factories[db_name] = sessionmaker(
                bind=engine,
                autocommit=False,
                autoflush=False
            )
        
        logger.info("✅ Database connections initialized")
    
    @contextmanager
    def session_scope(self, db_name: str = "mysql"):
        """提供事务性会话"""
        
        session = self.session_factories[db_name]()
        
        try:
            yield session
            session.commit()
        except Exception as e:
            session.rollback()
            logger.error(f"Database error in {db_name}: {e}")
            raise
        finally:
            session.close()
    
    def get_session(self, db_name: str = "mysql") -> Session:
        """获取会话（需要手动管理）"""
        return self.session_factories[db_name]()
    
    def close_all(self):
        """关闭所有数据库连接"""
        for db_name, engine in self.engines.items():
            engine.dispose()
            logger.info(f"Closed {db_name} connection")
```

@dataclass

    event_type: str  # INSERT, UPDATE, DELETE
    table_name: str
    source_db: str
    record_id: int
    timestamp: datetime
    data: Dict[str, Any]

            "event_type": self.event_type,
            "table_name": self.table_name,
            "source_db": self.source_db,
            "record_id": self.record_id,
            "timestamp": self.timestamp.isoformat(),

            return message_id

```
# apps/sync_service/worker.py
import asyncio
from typing import List

class SyncWorker:
    """同步Worker进程"""
    
    def __init__(self, worker_id: int, db_manager, sync_engine):
        self.worker_id = worker_id
        self.db_manager = db_manager
        self.sync_engine = sync_engine
        self.consumer_name = f"worker-{worker_id}"
        self.running = False
    
    async def start(self):
        """启动Worker"""
        self.running = True
        logger.info(f"Worker {self.worker_id} started")
        
        while self.running:
            try:
                # 从Stream读取事件
                events = self.sync_engine.redis.xreadgroup(
                    groupname=self.sync_engine.consumer_group,
                    consumername=self.consumer_name,
                    streams={self.sync_engine.stream_name: '>'},
                    count=10,
                    block=1000  # 阻塞1秒
                )
                
                if events:
                    for stream_name, messages in events:
                        for message_id, data in messages:
                            await self.process_event(message_id, data)
                
            except Exception as e:
                logger.error(f"Worker {self.worker_id} error: {e}")
                await asyncio.sleep(1)
    
    async def process_event(self, message_id: str, data: Dict):
        """处理同步事件"""
        
        try:
            # 解析事件数据
            event = SyncEvent(
                event_id=data["event_id"],
                event_type=data["event_type"],
                table_name=data["table_name"],
                source_db=data["source_db"],
                record_id=int(data["record_id"]),
                timestamp=datetime.fromisoformat(data["timestamp"]),
                data=json.loads(data["data"])
            )
            
            # 同步到其他数据库
            target_dbs = ["postgres", "mariadb", "sqlite"]
            if event.source_db in target_dbs:
                target_dbs.remove(event.source_db)
            
            for target_db in target_dbs:
                await self.sync_to_db(event, target_db)
            
            # 确认消息
            self.sync_engine.redis.xack(
                self.sync_engine.stream_name,
                self.sync_engine.consumer_group,
                message_id
            )
            
            # 更新统计
            self.sync_engine.redis.hincrby("campuswap:metrics", "events_consumed", 1)
            
            logger.debug(f"Processed event {event.event_id}")
            
        except Exception as e:
            logger.error(f"Failed to process event {message_id}: {e}")
    
    async def sync_to_db(self, event: SyncEvent, target_db: str):
        """同步数据到目标数据库"""
        
        try:
            with self.db_manager.session_scope(target_db) as session:
                if event.event_type == "INSERT":
                    # 插入记录
                    model_class = get_model_class(event.table_name)
                    record = model_class(**event.data)
                    session.add(record)
                    
                elif event.event_type == "UPDATE":
                    # 更新记录
                    model_class = get_model_class(event.table_name)
                    record = session.get(model_class, event.record_id)
                    
                    if record:
                        for key, value in event.data.items():
                            setattr(record, key, value)
                    else:
                        # 记录不存在，插入新记录
                        record = model_class(**event.data)
                        session.add(record)
                    
                elif event.event_type == "DELETE":
                    # 删除记录
                    model_class = get_model_class(event.table_name)
                    record = session.get(model_class, event.record_id)
                    if record:
                        session.delete(record)
                
                session.commit()
                
                logger.debug(
                    f"Synced {event.event_type} {event.table_name}:{event.record_id} "
                    f"from {event.source_db} to {target_db}"
                )
                
        except Exception as e:
            logger.error(
                f"Failed to sync to {target_db}: {e}",
                extra={
                    "event": event.event_id,
                    "table": event.table_name,
                    "record_id": event.record_id
                }
            )
            
            # 记录冲突
            await self.record_conflict(event, target_db, str(e))
    
    async def record_conflict(self, event: SyncEvent, target_db: str, error: str):
        """记录同步冲突"""
        
        with self.db_manager.session_scope("mysql") as session:
            conflict = ConflictRecord(
                table_name=event.table_name,
                record_id=event.record_id,
                source_db=event.source_db,
                target_db=target_db,
                conflict_type="sync_error",
                source_data=event.data,
                target_data={},
                error_message=error,
                status="pending",
                created_at=datetime.utcnow()
            )
            session.add(conflict)
            session.commit()

# 启动多个Worker
async def start_sync_workers(num_workers: int = 4):
    """启动多个同步Worker"""
    
    workers = []
    for i in range(num_workers):
        worker = SyncWorker(i, db_manager, sync_engine)
        workers.append(worker)
        asyncio.create_task(worker.start())
    
    logger.info(f"Started {num_workers} sync workers")
    return workers
```

### 6.2.2 Pinia状态管理

```typescript
// src/stores/item.ts
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'
import type { Item, ItemFilter } from '@/types'
import { api } from '@/lib/api'

export const useItemStore = defineStore('item', () => {
  // 状态
  const items = ref<Item[]>([])
  const currentItem = ref<Item | null>(null)
  const loading = ref(false)
  const error = ref<string | null>(null)
  
  // 分页
  const page = ref(1)
  const pageSize = ref(20)
  const total = ref(0)
  
  // 过滤条件
  const filter = ref<ItemFilter>({
    status: 'available',
    categoryId: null,
    minPrice: null,
    maxPrice: null,
    keyword: ''
  })
  
  // 计算属性
  const hasMore = computed(() => {
    return items.value.length < total.value
  })
  
  const availableItems = computed(() => {
    return items.value.filter(item => item.status === 'available')
  })
  
  // 操作
  async function fetchItems(resetPage = false) {
    if (resetPage) {
      page.value = 1
      items.value = []
    }
    
    loading.value = true
    error.value = null
    
    try {
      const response = await api.get('/items', {
        params: {
          page: page.value,
          page_size: pageSize.value,
          ...filter.value
        }
      })
      
      if (resetPage) {
        items.value = response.data.items
      } else {
        items.value.push(...response.data.items)
      }
      
      total.value = response.data.total
      page.value++
      
    } catch (err: any) {
      error.value = err.message || 'Failed to fetch items'
      throw err
    } finally {
      loading.value = false
    }
  }
  
  async function fetchItemDetail(itemId: number) {
    loading.value = true
    error.value = null
    
    try {
      const response = await api.get(`/items/${itemId}`)
      currentItem.value = response.data
      
      // 增加浏览次数
      await api.post(`/items/${itemId}/view`)
      
    } catch (err: any) {
      error.value = err.message || 'Failed to fetch item detail'
      throw err
    } finally {
      loading.value = false
    }
  }
  
  async function createItem(itemData: Partial<Item>) {
    loading.value = true
    error.value = null
    
    try {
      const response = await api.post('/items', itemData)
      items.value.unshift(response.data)
      return response.data
    } catch (err: any) {
      error.value = err.message || 'Failed to create item'
      throw err
    } finally {
      loading.value = false
    }
  }
  
  async function updateItem(itemId: number, itemData: Partial<Item>) {
    loading.value = true
    error.value = null
    
    try {
      const response = await api.patch(`/items/${itemId}`, itemData)
      
      // 更新本地状态
      const index = items.value.findIndex(item => item.id === itemId)
      if (index !== -1) {
        items.value[index] = response.data
      }
      
      if (currentItem.value?.id === itemId) {
        currentItem.value = response.data
      }
      
      return response.data
    } catch (err: any) {
      error.value = err.message || 'Failed to update item'
      throw err
    } finally {
      loading.value = false
    }
  }
  
  async function favoriteItem(itemId: number) {
    await api.post(`/items/${itemId}/favorite`)
    
    // 更新收藏数
    const item = items.value.find(i => i.id === itemId)
    if (item) {
      item.favoriteCount++
    }
  }
  
  async function unfavoriteItem(itemId: number) {
    await api.delete(`/items/${itemId}/favorite`)
    
    // 更新收藏数
    const item = items.value.find(i => i.id === itemId)
    if (item) {
      item.favoriteCount--
    }
  }
  
  function updateFilter(newFilter: Partial<ItemFilter>) {
    filter.value = { ...filter.value, ...newFilter }
  }
  
  function resetFilter() {
    filter.value = {
      status: 'available',
      categoryId: null,
      minPrice: null,
      maxPrice: null,
      keyword: ''
    }
  }
  
  return {
    // 状态
    items,
    currentItem,
    loading,
    error,
    page,
    pageSize,
    total,
    filter,
    
    // 计算属性
    hasMore,
    availableItems,
    
    // 操作
    fetchItems,
    fetchItemDetail,
    createItem,
    updateItem,
    favoriteItem,
    unfavoriteItem,
    updateFilter,
    resetFilter
  }
})
```

### 6.2.3 WebSocket实时通信

```typescript
// src/lib/websocket.ts
import { ref, onUnmounted } from 'vue'
import { useAuthStore } from '@/stores/auth'

export class WebSocketClient {
  private ws: WebSocket | null = null
  private reconnectTimer: number | null = null
  private heartbeatTimer: number | null = null
  private messageHandlers: Map<string, Function[]> = new Map()
  
  public connected = ref(false)
  public connecting = ref(false)
  
  constructor(private url: string) {}
  
  connect() {
    if (this.ws?.readyState === WebSocket.OPEN) {
      return
    }
    
    this.connecting.value = true
    
    const authStore = useAuthStore()
    const token = authStore.token
    
    // 连接WebSocket
    this.ws = new WebSocket(`${this.url}?token=${token}`)
    
    this.ws.onopen = () => {
      console.log('WebSocket connected')
      this.connected.value = true
      this.connecting.value = false
      this.startHeartbeat()
    }
    
    this.ws.onmessage = (event) => {
      try {
        const message = JSON.parse(event.data)
        this.handleMessage(message)
      } catch (error) {
        console.error('Failed to parse WebSocket message:', error)
      }
    }
    
    this.ws.onerror = (error) => {
      console.error('WebSocket error:', error)
    }
    
    this.ws.onclose = () => {
      console.log('WebSocket disconnected')
      this.connected.value = false
      this.connecting.value = false
      this.stopHeartbeat()
      this.scheduleReconnect()
    }
  }
  
  disconnect() {
    if (this.reconnectTimer) {
      clearTimeout(this.reconnectTimer)
      this.reconnectTimer = null
    }
    
    if (this.ws) {
      this.ws.close()
      this.ws = null
    }
  }
  
  send(type: string, data: any) {
    if (this.ws?.readyState === WebSocket.OPEN) {
      this.ws.send(JSON.stringify({ type, data }))
    } else {
      console.warn('WebSocket is not connected')
    }
  }
  
  on(type: string, handler: Function) {
    if (!this.messageHandlers.has(type)) {
      this.messageHandlers.set(type, [])
    }
    this.messageHandlers.get(type)!.push(handler)
  }
  
  off(type: string, handler: Function) {
    const handlers = this.messageHandlers.get(type)
    if (handlers) {
      const index = handlers.indexOf(handler)
      if (index !== -1) {
        handlers.splice(index, 1)
      }
    }
  }
  
  private handleMessage(message: any) {
    const handlers = this.messageHandlers.get(message.type)
    if (handlers) {
      handlers.forEach(handler => handler(message.data))
    }
  }
  
  private startHeartbeat() {
    this.heartbeatTimer = window.setInterval(() => {
      this.send('ping', {})
    }, 30000) // 每30秒发送心跳
  }
  
  private stopHeartbeat() {
    if (this.heartbeatTimer) {
      clearInterval(this.heartbeatTimer)
      this.heartbeatTimer = null
    }
  }
  
  private scheduleReconnect() {
    if (this.reconnectTimer) return
    
    this.reconnectTimer = window.setTimeout(() => {
      console.log('Attempting to reconnect WebSocket...')
      this.reconnectTimer = null
      this.connect()
    }, 5000) // 5秒后重连
  }
}

// 全局WebSocket实例
export const wsClient = new WebSocketClient(import.meta.env.VITE_WS_URL)

// 在组件中使用
export function useWebSocket() {
  onUnmounted(() => {
    // 组件卸载时不断开连接，保持全局连接
  })
  
  return wsClient
}
```
