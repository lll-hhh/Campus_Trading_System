# 第3章 多数据库同步机制

## 3.1 同步机制概述

### 3.1.1 同步需求分析

#### 课程要求回顾

根据《数据库系统实践》任务书的要求：

> （1）系统需同时支持不少于三种数据库系统，并实现跨库数据同步功能；
> （2）所有数据库中的表结构保持一致；
> （3）当任一数据库发生数据变更时，系统应立即将更新同步至其他数据库；
> （4）系统可根据配置周期自动执行同步任务；
> （5）数据冲突时自动邮件提醒管理员，管理员可选择数据来源进行修复。

#### 本系统实现方案

**支持的数据库：** ✅ 超出要求
- MySQL 8.0（主生产库）
- PostgreSQL 15（分析库）
- MariaDB 10.11（备份库）
- SQLite 3.x（开发测试库）

**数据一致性目标：**
- **最终一致性**：允许短暂的数据不一致，但最终达到一致状态
- **同步延迟**：目标 < 100ms（实时同步）
- **冲突解决**：自动检测 + 人工干预
- **数据完整性**：保证数据不丢失

**同步策略：**
1. **实时同步**：数据变更立即触发同步（INSERT/UPDATE/DELETE）
2. **周期同步**：定时全量或增量同步（防止遗漏）
3. **冲突检测**：乐观锁（版本号）机制
4. **冲突解决**：人工选择或自动重试

### 3.1.3 技术选型说明

#### 为什么选择Redis Stream？

**对比其他消息队列：**

| 特性 | Redis Stream | RabbitMQ | Kafka | 选择理由 |
|-----|-------------|----------|-------|---------|
| 部署复杂度 | 低 | 中 | 高 | ✅ 简单 |
| 性能 | 高 | 中 | 高 | ✅ 满足需求 |
| 持久化 | 支持 | 支持 | 支持 | ✅ 数据安全 |
| 消息顺序 | 保证 | 保证 | 保证 | ✅ 重要 |
| 轻量级 | 是 | 否 | 否 | ✅ 校园项目 |
| 学习成本 | 低 | 中 | 高 | ✅ 易上手 |

**Redis Stream优势：**
1. 系统已使用Redis做缓存，无需额外部署
2. 性能足够支持校园级别的并发
3. 持久化保证消息不丢失
4. 消费组机制支持多实例
5. 操作简单，代码量少

#### 为什么使用乐观锁？

**乐观锁 vs 悲观锁：**

| 维度 | 乐观锁（Optimistic） | 悲观锁（Pessimistic） |
|-----|---------------------|---------------------|
| 冲突假设 | 冲突较少 ✅ | 冲突频繁 |
| 性能 | 高（无锁等待）✅ | 低（锁竞争） |
| 并发度 | 高 ✅ | 低 |
| 实现方式 | 版本号 | SELECT FOR UPDATE |
| 适用场景 | 读多写少 ✅ | 写多读少 |
| 分布式 | 天然支持 ✅ | 需要分布式锁 |

**本系统选择乐观锁的原因：**
1. 校园交易系统读多写少
2. 多数据库环境，分布式锁复杂
3. 性能要求高，避免锁等待
4. 冲突概率低，即使冲突也可人工解决

**乐观锁实现：sync_version字段**
```sql
-- 每张表都有sync_version字段
sync_version INT DEFAULT 0

-- 更新时检查版本号
UPDATE items 
SET price = 100, sync_version = sync_version + 1
WHERE id = 123 AND sync_version = 5;

-- 如果affected_rows = 0，说明版本冲突
```

**SyncEvent数据结构：**
```python
@dataclass
class SyncEvent:
    """同步事件的标准化表示"""
    
    table: str              # 表名，如 "items"
    action: str             # 操作类型："insert", "update", "delete"
    payload: Dict[str, Any] # 数据负载（SQL语句+参数）
    origin: str             # 源数据库："mysql", "postgres"等
    occurred_at: datetime   # 发生时间
    sync_version: int       # 同步版本号
    record_id: Optional[str] = None  # 记录ID（用于追踪）
    
    def as_message(self) -> Dict[str, Any]:
        """序列化为Redis消息"""
        return {
            "table": self.table,
            "action": self.action,
            "payload": json.dumps(self.payload, default=str),
            "origin": self.origin,
            "occurred_at": self.occurred_at.isoformat(),
            "sync_version": self.sync_version,
            "record_id": self.record_id or "",
        }
```

### 3.2.2 事件消费与复制

#### 消费者Worker实现

```python
class SyncWorker:
    """同步工作进程，消费Redis Stream事件"""
    
    def __init__(self, worker_id: str):
        self.worker_id = worker_id
        self.redis = redis.Redis.from_url(settings.redis_url)
        self.stream_key = "campuswap:sync:events"
        self.group_name = "sync_workers"
        self.running = False
    
    def start(self):
        """启动消费者"""
        self.running = True
        logger.info(f"Worker {self.worker_id} started")
        
        # 创建消费组（如果不存在）
        try:
            self.redis.xgroup_create(
                self.stream_key, 
                self.group_name, 
                id='0', 
                mkstream=True
            )
        except redis.ResponseError as e:
            if 'BUSYGROUP' not in str(e):
                raise
        
        # 持续消费消息
        while self.running:
            try:
                # 读取消息（阻塞5秒）
                messages = self.redis.xreadgroup(
                    groupname=self.group_name,
                    consumername=self.worker_id,
                    streams={self.stream_key: '>'},
                    count=10,
                    block=5000
                )
                
                if messages:
                    self._process_messages(messages)
                    
            except Exception as e:
                logger.error(f"Worker error: {e}")
                time.sleep(1)
    
    def _process_messages(self, messages):
        """处理消息批次"""
        for stream_name, message_list in messages:
            for message_id, data in message_list:
                try:
                    # 解析事件
                    event = SyncEvent.from_stream(data)
                    
                    # 确定目标数据库
                    targets = self._get_target_dbs(event.origin)
                    
                    # 执行同步
                    sync_engine.replicate(event, targets)
                    
                    # 确认消息
                    self.redis.xack(
                        self.stream_key, 
                        self.group_name, 
                        message_id
                    )
                    
                    logger.info(
                        f"Synced {event.table}.{event.record_id} "
                        f"from {event.origin} to {targets}"
                    )
                    
                except Exception as e:
                    logger.error(f"Failed to process message: {e}")
                    # 消息会自动重试
    
    def _get_target_dbs(self, origin: str) -> List[str]:
        """获取目标数据库列表（排除源数据库）"""
        all_dbs = ["mysql", "postgres", "mariadb", "sqlite"]
        return [db for db in all_dbs if db != origin]
```

#### 数据复制逻辑

```python
def replicate(self, event: SyncEvent, targets: Iterable[str]) -> None:
    """将事件复制到目标数据库"""
    
    for target in targets:
        try:
            with db_manager.session_scope(target) as session:
                # 执行SQL语句
                statement = text(event.payload["statement"])
                params = decode_params(event.payload.get("params", {}))
                
                result = session.execute(statement, params)
                
                # 检查影响行数（乐观锁检测）
                if event.action in {"update", "delete"} and result.rowcount == 0:
                    # 版本冲突！
                    logger.warning(
                        f"Sync conflict detected: {event.table}.{event.record_id} "
                        f"in {target}, expected version {event.sync_version-1}"
                    )
                    
                    # 记录冲突
                    self._record_conflict(event, target)
                    
                    # 发送邮件通知
                    self._notify_admin(event, target)
                    
                else:
                    # 同步成功
                    logger.info(
                        f"Replicated {event.table}.{event.record_id} "
                        f"to {target} successfully"
                    )
                    
        except Exception as e:
            logger.error(f"Failed to replicate to {target}: {e}")
            # 记录失败，后续重试
```

#### 批量同步优化

```python
def batch_replicate(self, events: List[SyncEvent], target: str) -> None:
    """批量同步，提升性能"""
    
    if not events:
        return
    
    success_count = 0
    failed_count = 0
    conflict_count = 0
    
    with db_manager.session_scope(target) as session:
        for event in events:
            try:
                statement = text(event.payload["statement"])
                params = decode_params(event.payload["params"])
                result = session.execute(statement, params)
                
                if event.action in {"update", "delete"} and result.rowcount == 0:
                    conflict_count += 1
                    self._record_conflict(event, target)
                else:
                    success_count += 1
                    
            except Exception as e:
                failed_count += 1
                logger.error(f"Batch sync error: {e}")
        
        # 批量提交
        session.commit()
    
    logger.info(
        f"Batch sync to {target}: "
        f"{success_count} success, {failed_count} failed, "
        f"{conflict_count} conflicts"
    )
```

```python
class PeriodicSyncScheduler:

    def __init__(self):
        self.scheduler = BackgroundScheduler(
            timezone='UTC',
            job_defaults={
                'coalesce': True,      # 合并错过的任务

        # 1. 每小时执行增量同步

            func=self.incremental_sync,
            trigger=CronTrigger(minute=0),  # 每小时第0分钟
            id='incremental_sync',
            name='增量同步任务',
            replace_existing=True
        )
        
        # 2. 每天凌晨3点执行全量同步

            func=self.full_sync,
            trigger=CronTrigger(hour=3, minute=0),
            id='full_sync',
            name='全量同步任务',
            replace_existing=True
        )
        
        # 3. 每10分钟检查同步健康度
        self.scheduler.add_job(
            func=self.health_check,

            minutes=10,
            id='health_check',
```

### 3.3.2 增量同步实现

```python
def incremental_sync(self):
    """增量同步：只同步最近变更的数据"""
    
    logger.info("Starting incremental sync...")
    start_time = datetime.utcnow()
    
    # 1. 确定同步时间窗口（最近1小时）
    time_window = timedelta(hours=1)
    since = start_time - time_window
    
    # 2. 查询各表的变更数据
    tables_to_sync = [
        'items', 'transactions', 'messages', 
        'comments', 'favorites'
    ]
    
    total_synced = 0
    
    for table in tables_to_sync:
        try:
            # 查询最近变更的记录
            synced = self._sync_table_incremental(table, since)
            total_synced += synced
            
        except Exception as e:
            logger.error(f"Failed to sync table {table}: {e}")
    
    duration = (datetime.utcnow() - start_time).total_seconds()
    
    # 3. 记录同步日志
    self._log_sync_result(
        sync_type='incremental',
        tables_synced=len(tables_to_sync),
        records_synced=total_synced,
        duration_seconds=duration
    )
    
    logger.info(
        f"Incremental sync completed: "
        f"{total_synced} records in {duration:.2f}s"
    )

def _sync_table_incremental(self, table: str, since: datetime) -> int:
    """同步单表的增量数据"""
    
    # 从主库（MySQL）读取变更数据
    with db_manager.session_scope("mysql") as session:
        # 查询最近更新的记录
        query = f"""
            SELECT * FROM {table}
            WHERE updated_at >= :since
            ORDER BY updated_at
        """
        result = session.execute(text(query), {"since": since})
        records = result.fetchall()
    
    if not records:
        return 0
    
    # 同步到其他数据库
    target_dbs = ["postgres", "mariadb", "sqlite"]
    synced_count = 0
    
    for target in target_dbs:
        with db_manager.session_scope(target) as session:
            for record in records:
                try:
                    # 使用UPSERT逻辑（存在则更新，不存在则插入）
                    self._upsert_record(session, table, record)
                    synced_count += 1
                except Exception as e:
                    logger.error(f"Failed to sync record: {e}")
            
            session.commit()
    
    return synced_count
```

### 3.3.3 全量同步实现

```python
def full_sync(self):
    """全量同步：同步所有数据（通常在凌晨执行）"""
    
    logger.info("Starting full sync...")
    start_time = datetime.utcnow()
    
    # 1. 所有需要同步的表
    all_tables = [
        # 核心业务表
        'users', 'categories', 'items', 'item_images',
        'comments', 'transactions', 'messages', 
        'favorites', 'reports',
        
        # 权限表
        'roles', 'permissions', 'user_roles', 
        'role_permissions', 'user_profiles',
        
        # 扩展表
        'cart_items', 'conversations', 'notifications'
    ]
    
    total_synced = 0
    failed_tables = []
    
    # 2. 逐表同步
    for table in all_tables:
        try:
            count = self._sync_table_full(table)
            total_synced += count
            logger.info(f"Synced table {table}: {count} records")
            
        except Exception as e:
            logger.error(f"Failed to sync table {table}: {e}")
            failed_tables.append(table)
    
    duration = (datetime.utcnow() - start_time).total_seconds()
    
    # 3. 生成同步报告
    self._generate_sync_report(
        sync_type='full',
        total_records=total_synced,
        duration=duration,
        failed_tables=failed_tables
    )
    
    # 4. 如果有失败，发送告警
    if failed_tables:
        self._send_alert(f"Full sync failed for tables: {failed_tables}")

def _sync_table_full(self, table: str) -> int:
    """全量同步单表"""
    
    # 1. 从主库读取所有数据
    with db_manager.session_scope("mysql") as session:
        result = session.execute(text(f"SELECT * FROM {table}"))
        records = result.fetchall()
        columns = result.keys()
    
    if not records:
        return 0
    
    # 2. 同步到目标库
    target_dbs = ["postgres", "mariadb", "sqlite"]
    
    for target in target_dbs:
        with db_manager.session_scope(target) as session:
            # 清空目标表（谨慎！）
            # session.execute(text(f"TRUNCATE TABLE {table}"))
            
            # 批量插入
            for record in records:
                record_dict = dict(zip(columns, record))
                self._upsert_record(session, table, record_dict)
            
            session.commit()
            
            logger.info(f"Full sync {table} to {target}: {len(records)} records")
    
    return len(records) * len(target_dbs)
```

## 3.4 冲突检测与处理

### 3.4.1 冲突类型识别

#### 1. 版本冲突（Version Conflict）

**场景：** 同一记录在不同数据库被同时修改。

**检测方式：**
```python
# 更新时检查sync_version
UPDATE items 
SET price = 100, sync_version = sync_version + 1
WHERE id = 123 AND sync_version = 5;

# 如果 rowcount = 0，说明版本不匹配
# 可能的原因：
# 1. 记录已被其他事务修改（version > 5）
# 2. 记录被删除
```

**示例：**
```
时间线：
10:00:00  MySQL:    读取 item(id=123, price=100, version=5)
10:00:01  Postgres: 读取 item(id=123, price=100, version=5)
10:00:02  MySQL:    更新 item SET price=120, version=6 WHERE version=5 ✅
10:00:03  Postgres: 更新 item SET price=150, version=6 WHERE version=5 ✅
10:00:04  同步:     MySQL->Postgres: SET price=120, version=6 WHERE version=5 ❌
                   (Postgres已是version=6，更新失败！)
```

#### 2. 删除冲突（Delete Conflict）

**场景：** 一边删除记录，另一边修改记录。

**检测方式：**
```python
try:
    # 尝试更新
    result = session.execute(
        text("UPDATE items SET price = :price WHERE id = :id"),
        {"price": 100, "id": 123}
    )
    
    if result.rowcount == 0:
        # 检查记录是否存在
        exists = session.execute(
            text("SELECT 1 FROM items WHERE id = :id"),
            {"id": 123}
        ).fetchone()
        
        if not exists:
            # 删除冲突！
            raise DeleteConflictError(f"Record {123} was deleted")
except Exception as e:
    # 记录冲突
    ...
```

#### 3. 约束冲突（Constraint Conflict）

**场景：** 违反数据库约束（唯一键、外键等）。

**示例：**
```python
# 唯一键冲突
INSERT INTO users (username, email) 
VALUES ('zhangsan', 'zhangsan@csu.edu.cn')
# 如果username已存在，抛出IntegrityError

# 外键冲突

VALUES (999, 'Test Item', 100)
# 如果seller_id=999不存在，抛出IntegrityError
```

```python
def transfer_with_compensation(item_id: int, buyer_id: int):
    """带补偿机制的跨库操作"""
    
    executed_dbs = []  # 记录已执行的数据库
    
    try:
        # 1. 在主库执行
        with db_manager.session_scope("mysql") as session:
            item = session.get(Item, item_id)

            raise SyncFailureError("Sync failed", sync_result)
```

```python
def validate_transaction(transaction: Transaction) -> bool:
    """验证交易数据的一致性"""
```

```python
def check_cross_db_consistency(table: str, record_id: int) -> Dict:
    """检查记录在各数据库中的一致性"""
    
    all_dbs = ["mysql", "postgres", "mariadb", "sqlite"]
    records = {}
    
    # 1. 从各数据库读取记录
    for db in all_dbs:
        try:
            with db_manager.session_scope(db) as session:
                query = text(f"SELECT * FROM {table} WHERE id = :id")
                result = session.execute(query, {"id": record_id}).fetchone()
                
                if result:
                    records[db] = dict(result)
                else:
                    records[db] = None
                    
        except Exception as e:
            logger.error(f"Failed to read from {db}: {e}")
            records[db] = {"error": str(e)}
    
    # 2. 比较数据
    reference_data = records.get("mysql")  # 以主库为基准
    inconsistencies = []
    
    for db, data in records.items():
        if db == "mysql":
            continue
        
        if data is None and reference_data is not None:
            inconsistencies.append({
                "db": db,
                "issue": "Record missing",
                "reference": reference_data
            })
        elif data != reference_data:
            # 比较字段差异
            diff = compare_records(reference_data, data)
            if diff:
                inconsistencies.append({
                    "db": db,
                    "issue": "Data mismatch",
                    "diff": diff
                })
    
    return {
        "table": table,
        "record_id": record_id,
        "is_consistent": len(inconsistencies) == 0,
        "records": records,
        "inconsistencies": inconsistencies
    }
```

### 3.5.2 最终一致性模型

#### CAP理论权衡

在分布式系统中，CAP理论指出只能同时满足以下三个特性中的两个：
- **C（Consistency）**：一致性
- **A（Availability）**：可用性
- **P（Partition Tolerance）**：分区容错性

**本系统的选择：AP > C**

由于是多数据库系统，网络分区是必然存在的，因此：
- **保证A（可用性）**：单个数据库故障不影响服务
- **保证P（分区容错）**：支持数据库间的网络隔离
- **放宽C（一致性）**：采用最终一致性而非强一致性

```
┌────────────────────────────────────────┐
│          强一致性 vs 最终一致性          │
├────────────────────────────────────────┤
│                                        │
│  强一致性（不可行）：                    │
│  ┌──────┐       ┌──────┐              │
│  │MySQL│◄─────►│Postgres│             │
│  └──────┘   同步  └──────┘              │
│     ↓           ↓                      │
│  阻塞等待    阻塞等待                    │
│  性能差      可用性差                    │
│                                        │
│  最终一致性（本系统）：                   │
│  ┌──────┐       ┌──────┐              │
│  │MySQL│──异步──►│Postgres│            │
│  └──────┘       └──────┘              │
│     ↓             ↓                    │
│  立即返回      延迟更新                  │
│  性能好        可用性高                  │
│  (短暂不一致, 最终一致)                 │
└────────────────────────────────────────┘
```

```python
                func.date(SyncLog.started_at) == target_date
```
