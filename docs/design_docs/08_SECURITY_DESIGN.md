# 凤凰汽配管理系统 - 安全设计文档

## 1. 安全架构概述
凤凰汽配管理系统将安全性视为生命线。由于系统涉及零件成本、客户隐私及交易资金，我们采用了多层防御体系（Defense in Depth），从网络层、应用层到数据层进行全方位防护。

## 2. 身份认证与访问控制 (IAM)

### 2.1 身份认证 (Authentication)
- **JWT 机制**：系统采用无状态的 JWT (JSON Web Token) 进行身份验证。
  - **签名算法**：HS256。
  - **载荷内容**：包含 `sub` (用户 ID), `exp` (过期时间), `iat` (签发时间)。
  - **刷新机制**：支持 Refresh Token 机制，Access Token 有效期 2 小时，Refresh Token 有效期 7 天。
- **多因素认证 (MFA)**：针对管理员账号，系统预留了 TOTP (Google Authenticator) 接口，可开启二次验证。

### 2.2 访问控制 (Authorization)
- **RBAC 模型**：基于角色的访问控制。
  - **角色 (Role)**：如超级管理员、仓库员、销售员。
  - **权限 (Permission)**：如 `part:create`, `order:cancel`, `user:manage`。
- **权限校验流程**：
  1. 用户请求 API。
  2. 后端中间件解析 JWT，获取用户角色。
  3. 查询 Redis 缓存中的角色-权限映射表。
  4. 判断当前用户是否拥有该 API 所需的权限。
  5. 若无权限，返回 `403 Forbidden`。

## 3. 数据安全与加密

### 3.1 传输加密
- **HTTPS 强制**：所有外部通信必须通过 TLS 1.2+ 协议。
- **HSTS 策略**：开启 HTTP 严格传输安全，防止降级攻击。

### 3.2 存储加密
- **密码哈希**：使用 `Argon2id` 算法，配合随机盐值（Salt），防止彩虹表攻击。
- **敏感字段加密**：对于数据库中的客户手机号、身份证号等敏感信息，采用 `AES-256-GCM` 对称加密存储，密钥由环境变量管理。

### 3.3 数据脱敏
- **前端脱敏**：在展示界面，对敏感信息进行遮蔽处理（如：138****8888）。
- **后端脱敏**：API 返回数据时，通过 Pydantic 的 `exclude` 机制自动过滤敏感字段。

## 4. 应用层安全防护

### 4.1 防 SQL 注入
- **ORM 强制使用**：严禁在业务代码中拼接 SQL 字符串，必须使用 SQLAlchemy 的参数化查询。

### 4.2 防 XSS 攻击
- **输入过滤**：前端使用 Vue 3 默认的模板转义机制。
- **CSP 策略**：配置 Content Security Policy，限制外部脚本的加载来源。

### 4.3 防 CSRF 攻击
- **JWT 免疫**：由于系统不使用 Cookie 存储身份信息，天然免疫 CSRF 攻击。

### 4.4 频率限制 (Rate Limiting)
- **滑动窗口算法**：基于 Redis 实现，针对不同接口设置不同的阈值。
- **黑名单机制**：对于短时间内触发多次 403/401 错误的 IP，自动封禁 1 小时。

## 5. 审计与监控

### 5.1 操作审计日志 (Audit Logs)
系统记录所有“写”操作的详细日志：
- **Who**：操作人 ID 及用户名。
- **When**：精确到毫秒的操作时间。
- **Where**：操作人的 IP 地址及地理位置（基于 IP 库）。
- **What**：操作的 API 路径、请求参数、修改前后的数据对比（Diff）。

### 5.2 异常监控
- **Sentry 集成**：后端发生 500 错误时，自动将堆栈信息推送至 Sentry。
- **实时告警**：对于连续的登录失败或大额订单取消，通过钉钉/邮件向安全管理员发送告警。

## 6. 攻击防御深度解析 (Attack Defense)

### 6.1 SQL 注入防御
- **机制**：全量使用 SQLAlchemy ORM，禁止拼接 SQL 字符串。
- **校验**：在 Pydantic 模型中对所有输入进行严格类型检查。
- **示例**：
  ```python
  # 错误做法
  # db.execute(f"SELECT * FROM parts WHERE name = '{user_input}'")
  # 正确做法
  db.query(Part).filter(Part.name == user_input).all()
  ```

### 6.2 XSS 跨站脚本攻击防御
- **前端**：Vue 3 默认对插值内容进行转义。
- **后端**：对用户提交的 HTML 内容进行清洗（使用 `bleach` 库）。
- **Header**：设置 `Content-Security-Policy` (CSP) 限制外部脚本加载。

### 6.3 CSRF 跨站请求伪造防御
- **机制**：由于采用 JWT + Bearer Token 模式，且不使用 Cookie 存储 Token，天然免疫 CSRF。
- **增强**：对于敏感操作，要求前端在 Header 中携带自定义随机数。

### 6.4 暴力破解防御
- **限流**：使用 Redis 记录登录失败次数，5 分钟内失败 5 次锁定账号 15 分钟。
- **验证码**：在登录失败 3 次后强制要求输入图形验证码。

## 7. 合规性与审计清单 (Compliance)

### 7.1 个人信息保护 (PII)
- **脱敏显示**：前端显示手机号时中间四位隐藏（如 138****1234）。
- **加密存储**：身份证号、银行卡号等敏感信息在数据库中加密存储。

### 7.2 操作审计日志规范
- **记录内容**：操作人 ID、操作时间、操作模块、操作类型（增删改）、操作前数据、操作后数据、客户端 IP。
- **存储周期**：审计日志至少保留 180 天。

### 7.3 安全漏洞扫描
- **静态扫描**：集成 `Bandit` 到 CI/CD 流程，扫描 Python 代码安全隐患。
- **动态扫描**：定期使用 `OWASP ZAP` 对运行中的系统进行渗透测试。

## 8. 应急响应预案 (Incident Response)

### 8.1 账号被盗响应
1. 立即冻结受影响账号。
2. 强制注销该账号的所有活跃 JWT 会话（通过 Redis 黑名单）。
3. 通知用户修改密码。

### 8.2 数据泄露响应
1. 启动应急小组，定位泄露源头。
2. 封堵漏洞，切断泄露途径。
3. 评估泄露范围，按法律要求通知监管部门和受影响用户。

### 8.3 安全事件响应流程 (IRP)

当发生安全事件（如数据泄露或系统遭入侵）时，应遵循以下流程：

1.  **识别 (Identification)**：通过监控告警或日志审计确认安全事件。
2.  **抑制 (Containment)**：
    -   短期抑制：隔离受影响的服务器，修改受影响账户的密码。
    -   长期抑制：修复漏洞，重新部署干净的系统镜像。
3.  **根除 (Eradication)**：删除攻击者留下的后门、恶意脚本，清理受污染的数据。
4.  **恢复 (Recovery)**：从最近的干净备份中恢复数据，逐步恢复业务运行。
5.  **总结 (Lessons Learned)**：编写事故报告，分析原因，改进安全防护措施。

### 8.4 威胁建模与风险评估 (STRIDE 模型)

针对凤凰汽配管理系统，我们采用微软的 STRIDE 模型进行威胁建模：

| 威胁类别 | 描述 | 缓解措施 |
| :--- | :--- | :--- |
| **S**poofing (身份欺骗) | 攻击者伪造合法用户身份登录系统 | 强制使用 JWT 令牌，设置合理的过期时间，实施多因素认证 (MFA) 建议 |
| **T**ampering (数据篡改) | 攻击者在传输过程中或数据库中修改订单或库存数据 | 使用 HTTPS 加密传输，数据库字段级加密，实施数据完整性校验 (HMAC) |
| **R**epudiation (抵赖) | 用户否认执行过敏感操作（如删除订单） | 完善的操作审计日志，记录用户 ID、IP、时间戳及操作详情 |
| **I**nformation Disclosure (信息泄露) | 攻击者获取客户隐私或商业机密（如进货价） | 严格的 RBAC 权限控制，敏感字段脱敏显示，生产环境禁用调试模式 |
| **D**enial of Service (拒绝服务) | 攻击者通过大量请求瘫痪系统 | Nginx 速率限制 (Rate Limiting)，Redis 缓存减轻数据库压力，CDN 防护 |
| **E**levation of Privilege (权限提升) | 普通员工获取管理员权限修改系统配置 | 严格的后端权限校验（不依赖前端隐藏按钮），定期进行权限审计 |

### 8.6 安全代码示例 (Python/FastAPI)

#### 8.6.1 敏感数据加密工具类
```python
from cryptography.fernet import Fernet
import os

class DataEncryptor:
    """
    用于对数据库中的敏感字段（如供应商联系人手机号）进行加解密
    """
    def __init__(self):
        self.key = os.getenv("DATA_ENCRYPTION_KEY").encode()
        self.cipher_suite = Fernet(self.key)

    def encrypt(self, plain_text: str) -> str:
        if not plain_text:
            return None
        return self.cipher_suite.encrypt(plain_text.encode()).decode()

    def decrypt(self, encrypted_text: str) -> str:
        if not encrypted_text:
            return None
        return self.cipher_suite.decrypt(encrypted_text.encode()).decode()
```

#### 8.6.2 密码哈希处理
```python
from passlib.context import CryptContext

pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

def verify_password(plain_password, hashed_password):
    return pwd_context.verify(plain_password, hashed_password)

def get_password_hash(password):
    return pwd_context.hash(password)
```

## 10. API 安全与限流策略 (API Security)

### 10.1 身份验证 (Authentication)
- **机制**：基于 JWT (JSON Web Token) 的无状态认证。
- **算法**：HS256。
- **有效期**：Access Token (2 小时)，Refresh Token (7 天)。
- **存储**：前端存储在 `localStorage` 中，请求时放在 `Authorization: Bearer <token>`。

### 10.2 权限控制 (Authorization)
- **模型**：RBAC (Role-Based Access Control)。
- **粒度**：支持菜单级、按钮级、接口级权限控制。
- **实现**：后端使用 FastAPI 依赖注入校验用户角色和权限位。

### 10.3 流量控制 (Rate Limiting)
- **全局限流**：每个 IP 每秒最多 20 个请求。
- **登录限流**：每个 IP 每分钟最多 5 次登录尝试。
- **搜索限流**：每个用户每秒最多 2 次复杂搜索请求。
- **实现**：使用 Redis 存储计数器，配合 Lua 脚本保证原子性。

### 10.4 数据传输安全
- **HTTPS**：全站强制开启 TLS 1.2+，使用 Let's Encrypt 证书。
- **敏感数据加密**：
  - 数据库密码：使用 `bcrypt` 进行加盐哈希。
  - 配置文件密钥：使用环境变量或加密存储，禁止明文提交至 Git。

5. **恢复阶段**：逐步恢复服务，持续监控系统状态。
